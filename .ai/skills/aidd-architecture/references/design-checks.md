# 설계 증거 점검표

- 배포·운영 맥락 게이트: 온프레미스·클라우드, 실행 플랫폼, DBMS·데이터 토폴로지, 단일·다중 인스턴스, 자동 확장, 워크로드·데이터 증가, SLO·RTO·RPO, 로컬 상태 허용, 운영 책임과 미결 결정.
- 기술 스택 게이트: 유효한 배포 프로필, 성과·요구·품질 속성·제약, 현행 유지안을 포함한 후보, 타임박스 실험, 지원 수명, 팀·AI 역량, 비용·종속·가역성, ADR, 승인된 기술 기준선과 재검토 조건.
- 제품/UX: 사용자 여정, 정보 구조, 로딩·빈 화면·오류·권한 상태, 키보드·스크린리더 동작, 반응형 레이아웃, 재사용 패턴.
- 애플리케이션: 경계, `IFC` 계약, `DPN` 의존 방향·상태·검증, 업무 불변 조건, 트랜잭션과 외부 부작용, 프록시 기반 AOP 자기 호출·비관리 객체 우회, 스레드 전환 시 트랜잭션·보안·추적 컨텍스트, 멱등성, 재시도·순서, 실패 격리, 버전 관리.
- 데이터/DBA: 개념·논리 모델, 소유권, 분류, 계보, 보존, 마이그레이션, 인덱스, 백업·복구.
- 보안/개인정보: 신뢰 경계, 위협·오용, 신원, 인가, 비밀정보, 로깅, 최소 수집, 공급망.
- 인프라/SRE: 환경, IaC, 용량, SLO, 텔레메트리, 경보, 배포, 롤백, 재해 복구, 다중 인스턴스 경쟁, 로컬 락·세션·캐시 가정, 스케줄 중복과 리더 장애.
- 전달: 테스트 경계, CI 게이트, 기능 플래그, 호환 기간, 운영자·사용자 문서.
- 기반 준비도: 저장소 골든 패스, 공통 컴포넌트, 코딩·오류·보안·테스트·관측성·배포·롤백 표준, 경쟁·중복·부하·포화·장애 주입 검증, 개발자 가이드, 자동 차단 게이트.

ID와 연결된 다이어그램 코드를 선호한다. 다이어그램은 뷰이며, 기반이 되는 경계와 계약은 정본 레코드 또는 실행 가능한 명세에 둔다.

점검표가 문서에 존재한다는 사실은 통과 증거가 아니다. 변경별 게이트 실행에서 각 종료 기준을 `pending`, `passed`, `failed`, `waived`로 판정하고 `passed`에는 실행·검토 증거를, `waived`에는 승인자·만료·보완 통제를 연결한다.
