# KIT-REQ-018-020 — 기존 프로젝트의 명시적 전환과 이력 보존

- 출처: 기존 Kit 점진 개편·호환성 보존 방향 / 계획 목표 8~11, 14~15
- 목적: 새 구조를 채택할 때 데이터·이력·의미를 잃거나 승인 상태를 발명하지 않는다.
- 대상·트리거: 프로젝트가 자체 변경으로 새 형식을 명시적으로 채택하는 경우.

## 요구 동작

- 지원하는 구형 입력·변환 범위·지원하지 않는 확장·새 정본 위치와 되돌림 조건을 공개한다. 자동 업그레이드·patch·merge·역동기화는 제공하지 않는다.
- 실제 전환 전 대상·변경 예상·누락 정보·호환성·원본 보존을 확인한다. 수동 절차와 필요 도구의 범위는 S03에서 결정하되 사용자의 명시적 채택 없이 실행하지 않는다.
- ID·참조·결정·과거 검증 이력을 보존한다. 구형 implemented/done/passed를 새 요구 검토·목업 승인으로 자동 승격하지 않는다. 부족한 필드는 미확인·재검토 필요로 남긴다.
- 알 수 없는 확장 필드·레코드를 조용히 버리지 않는다. 보존/매핑/미지원 처리와 사용자 판단 필요를 보고한다.
- 전환 뒤 쓰기 정본은 하나다. 부분 실패·중복 적용·구형/신형 혼합을 검출하고 원본이나 검증된 재개 지점으로 복구한다. 이후 사용자 변경까지 덮어쓰는 되돌림을 하지 않는다.

## 범위·관계

- 포함: 수신 프로젝트의 로컬 채택 절차, 실패 시 안전한 중단·복구와 데이터 보존 확인.
- 제외: 모든 과거 사설 확장을 자동 변환하는 보증, 기존 사용자 코드의 무조건적인 자동 수정.
- 관계: 006~010, 014~015, 018~019.

## 인수 기준

- AC-020-1: 지원 구형 입력의 전환 결과에서 ID·참조·역사적 결과가 보존되고 부족한 새 승인 조건은 미완료로 남는다.
- AC-020-2: 미지원 확장·충돌·부분 실패·재적용을 검출하며 원본 유실이나 이중 쓰기 정본이 발생하지 않는다.
- AC-020-3: 전환 미채택 시 원본은 불변이고 채택/되돌림 범위·한계·후속 재검토를 사용자가 확인할 수 있다.
- 검증 연결: ACC-020.
