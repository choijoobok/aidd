DEP-001 — AIDD 기반 구조 배포 프로필

  • **id:** DEP-001
  • **name:** AIDD 기반 구조 배포 프로필
  • **scope:** 이 저장소의 방법론 프레임워크와 CLI
  • **status:** accepted
  • **environment:** 개발자 로컬 또는 CI 실행 환경의 저장소 기반 CLI
  • **hosting:** 온프레미스·클라우드에 종속되지 않음
  • **runtime:** Node.js 22 이상 단기 실행 프로세스
  • **topology:** 호출 단위 단일 프로세스이며 장기 실행 서비스 인스턴스가 없음
  • **scaling:** 서비스 자동 확장 적용 대상 아님. 병렬 CI 작업은 격리된 체크아웃을 사용해야 함
  • **dbms:** 실행 DBMS 없음. UTF-8 무 BOM JSON과 Git이 정본 저장소 역할을 함
  • **state:** 공유 쓰기 저장소에서 동시 생성·동기화 명령을 실행하지 않는 것을 현재 운영 가정으로 함
  • **workload:** 프로젝트 크기의 JSON·Markdown 파일을 결정적으로 생성·검증하는 배치형 작업
  • **availability:** Git 이력과 저장소 복구 가능성이 기준이며 온라인 서비스 SLO·RTO·RPO는 적용 대상 아님
  • **security_operations:** 저장소 권한, 훅 신뢰 검토, CI 비밀정보 분리와 변경 검토를 사용함
  • **open_assumptions:** 실제 제품 파일럿에서는 별도 DEP 프로필을 만들고 DG-001을 다시 통과해야 함
  • **requirements:** REQ-001, REQ-013, REQ-020

정상 운영 점검

정본 변경 후 생성, 동기화, 검증과 변경 영역 테스트 순서로 실행한다. 생성 문서를 직접 수정하지 않고 전체 테스트는 영향 범위가 요구할 때만 실행한다.

```powershell node .ai/tools/aidd.mjs generate node .ai/tools/aidd.mjs sync-ai node .ai/tools/aidd.mjs validate node <변경 영역의 test 파일> ```

릴리스와 개발 시작 점검

개발 시작과 릴리스는 서로 다른 게이트다. 차단 메시지를 해소하거나 승인된 예외를 기록하기 전에는 상태를 올리지 않는다.

```powershell node .ai/tools/aidd.mjs development-check --change CHG-001 node .ai/tools/aidd.mjs release-check --release REL-001 ```

병합 영향 대응

병합 후 생성된 MRG 레코드의 영향 모듈, 충돌 해결 근거와 추가 테스트 결정을 기록한다. 필요한 재검토·재테스트는 담당자 없이 MRC로 남기고, PM·관리자의 오프라인 지시 뒤 실제 수행자·시각·결과·증거만 완료 기록에 남긴다.

  1. post-merge 훅이 만든 MRG ID를 확인한다.
  2. 양쪽 부모와 결과를 비교한다.
  3. assess-merge로 모듈·메모·추가 테스트 결정을 기록한다.
  4. add-merge-recheck으로 릴리스 차단 여부와 대상 모듈·TC를 기록하되 담당자는 배정하지 않는다.
  5. 필요한 재검토·회귀 테스트를 실행하고 EVD를 연결한 뒤 complete-merge-recheck으로 실제 수행 결과를 남긴다.

장애 복구

검증 실패 시 오류가 가리키는 정본을 수정하고 재생성한다. 정본 JSON이 손상되면 Git의 마지막 정상 커밋과 변경 기록을 비교해 복구하며 생성 문서에서 역으로 덮어쓰지 않는다.

  1. 현재 변경과 오류를 보존한다.
  2. UTF-8 BOM·JSON 구문·끊어진 ID·오래된 생성 문서 순으로 확인한다.
  3. 가장 작은 정본 수정을 적용한다.
  4. validate와 관련 회귀 테스트를 다시 실행한다.

보호 자산과 신뢰 경계
