# AIDD 개발·전달

1. 변경 ID와 등급, 영향 요구사항·모듈, 승인된 설계, 유효한 배포 프로필·기술 기준선, `TG-002` 기반 준비도, 적용 설계 위험, 테스트 전략, 마이그레이션과 롤백을 확인한다.
2. 작업을 검토 가능한 요구사항 크기의 증분으로 나눈다. 요구사항이 명시적으로 바꾸지 않은 기존 동작은 보존한다.
3. 승인된 기술 스택, UI 패턴과 공통 컴포넌트를 재사용한다. 모듈별 지침과 실행 가능한 계약을 따르며 재검토 조건이 발생하면 기능 개발을 계속하기 전에 기술 기준선을 다시 평가한다.
4. 코드, 테스트, 텔레메트리, 설정, 마이그레이션과 적용 가능한 개발자·운영자·사용자 문서를 같은 변경에서 구현한다.
5. 위험 기반 테스트를 사용한다. 경계에는 단위·계약 테스트, 의존성·데이터에는 통합 테스트, 핵심 여정에는 종단 간 테스트, 영향 동작에는 회귀 테스트를 적용한다. 배포 프로필과 설계가 요구하면 스레드 전환, 다중 프로세스 경쟁, 중복·재시도·순서 역전, 대표 데이터 부하·포화·복구, 의존 장애 주입과 보안 테스트를 수행한다.
6. 병합 충돌이 있으면 각 해결이 올바른 이유, 영향받는 모듈·파일, 달라졌을 수 있는 가정과 추가 테스트 결정을 기록한다.
7. 출시 전에 추적성, 테스트 결과, 보안 발견사항, 마이그레이션 연습, 롤백, 관측성, 지원 준비도와 잔여 위험 수용을 검증한다.
8. 생성·검증과 관련 빌드·테스트를 실행한다. 테스트 증거와 릴리스·변경 상태를 갱신하며, 코드가 존재한다는 이유만으로 요구사항을 완료 처리하지 않는다.

완료와 릴리스 게이트는 [references/done-and-release.md](references/done-and-release.md)를 읽는다.
