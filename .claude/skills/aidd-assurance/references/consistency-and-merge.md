# 정합성·추적성·레드팀·병합 검토

## 문서 정합성

정본 내부의 상충된 상태·소유자·버전·대체 관계와 정본-파생물 드리프트를 찾는다. 문구 유사성보다 같은 ID가 서로 다른 사실을 주장하는지 확인한다. 코드와 정본의 불일치는 어느 한쪽을 자동 승자로 정하지 않고 결함 또는 변경 후보로 기록한다.

## 추적성과 레드팀

`REQ → WRK/설계 → TC → EVD → GTR/APR`의 양방향 연결과 고아 ID를 확인한다. 정상 경로뿐 아니라 권한 오용, 중복·재시도, 순서 역전, 부분 성공, 의존 장애, 오래된 데이터, 접근성과 복구 실패를 공격한다. 발견사항은 심각도, 영향 ID, 증거, 결과와 최소 안전 수정안을 가진다.

## 병합 후 재검증

두 부모와 해결 결과를 비교하고 영향 모듈, 계약·표준·컴포넌트, 달라진 가정과 필요한 회귀 검사를 기록한다. 기존 완료 상태를 거짓으로 되돌리는 대신 `MRG` 아래에 대기 `MRC`를 만든다. `MRC`에는 대상 모듈·`TC`·릴리스 차단 여부를 두고, 프로젝트가 수행을 조율한 뒤 완료될 때만 실제 수행 주체·시각·결과·`EVD`를 기록한다. 필수 재검증이 남으면 완료 이력은 보존하되 현재 릴리스 준비는 차단 상태로 보고한다.
