# AIDD 요건 구현 검증

사용자가 검증을 요청한 범위만 빠르게 확인한다. 검증 자체를 위한 새 절차나 증거 체계를 만들지 않는다.

1. 적용할 정본을 먼저 확정한다. Kit에서는 `.ai/spec/`, `.ai/manifests/`, 루트 `AGENTS.md`를 사용하고, 프로젝트에서는 현재 `project/.aidd/ssot/`와 연결된 AIDD 명세를 사용한다. 과거 evidence, 생성물, fixture를 현재 요구사항으로 간주하지 않는다.
2. 요청 범위의 요건을 규칙·스킬·훅·도구의 관찰 가능한 동작에 연결한다. 존재 여부나 문구 검색만으로 통과시키지 말고 대표 정상·실패 입력으로 실제 동작을 확인한다.
3. 기본 검증은 빠른 구조 검사와 변경 영역의 작은 행위 테스트만 실행한다. 전체 fixture, 전체 테스트, export·new-project smoke는 관련 기반이나 생성기를 검증할 때만 실행한다.
4. 보안·권한·신원·서명 검사는 정본 요건에 명시되어 있고 요청 범위에 포함되거나, 사용자가 별도로 요청한 경우에만 수행한다. 검증자가 새 통제나 승인 조건을 임의로 만들지 않는다.
5. 파생 문서는 엄격하게 검증한다. 현재 정본으로 임시 위치에 다시 생성해 기대 파일 목록과 전체 내용을 비교하고, 누락·내용 차이·더 이상 생성 대상이 아닌 파일을 모두 보고한다. 생성물을 직접 고쳐 통과시키지 않는다.
6. 훅은 이벤트, 입력, 출력, 실패 동작과 provider 배선을 확인한다. 스킬은 트리거·범위·금지사항과 실제 수행 절차가 정본에 맞는지 확인한다. provider 복사본의 동일성은 내용의 정확성을 대신하지 않는다.
7. 결과는 `통과`, `실패`, `검증하지 않음`으로 구분하고 실행한 명령, 확인한 요건, 발견사항과 한계만 간결하게 보고한다. 사용자가 요구하지 않으면 별도 evidence 파일, 반복 독립 검토, 보안 감사 또는 릴리스 승인을 만들지 않는다.

작업공간 역할에 문서화된 빠른 검사와 관련 테스트 파일 하나로 시작한다. Kit 원본의 내부 명령과 smoke 조건은 배포되지 않는 관리자 가이드를 따르고, 프로젝트에서는 `validate`와 변경 영역 테스트를 기본으로 한다.
