# S04 — 작은 정본 파일·인덱스·조회 기반

APR-004의 연속 실행 승인으로 구현했다. 제출 design 묶음은 22개 그대로이며 정렬은 원 작성 도구의 localeCompare 기준으로 확인했다(ASCII 정렬과 달라 명시). ADR-006~009는 의미 변경 없이 accepted로 기록했다.

## 구현

- 소유자/타입/ID별 v2 저장, 공통 외피·해시·인덱스·실제 파일 기반 scope read.
- expected hash, operation 재실행, 짧은 lock, prepared 저널, 부분 복구 및 후속 사용자 수정 보존.
- v2 bootstrap과 CLI 라우팅. v1 fixture 회귀 경로 유지, v2에서 legacy writer 실행 차단.
- index/snapshot 보호 훅 4개를 각각 독립 수정. 등록 위치·명령 불변. 정본 스킬/가이드/실행 명세 동반 갱신.

## 검증

- record-store.test: 5/5. 모듈 오류 격리, 해시 투영, CAS/replay, 부분 복구, index 실패 및 동일 stat 변조.
- hook self-test, Kit check, generation/export/new-project smoke 통과.
- provider sync는 sandbox EPERM 후 허용된 재실행으로 완료.
- harness 기존 12건 중 초기 1건은 Codex shell의 path-only 입력 호환 회귀로 발견해 보완했으며 재실행 결과는 status.json에 기록한다.

## 남은 경계

요구/설계/개발 판정과 상세 생성은 S05~S07에서 연결한다. 미지원 v2 명령은 not_implemented로 실패하며 통과를 발명하지 않는다. 전원 장애·분산 파일시스템 완전 원자성 보증이나 실제 제품 마이그레이션은 포함하지 않는다. S08의 전체 provider 실제 수행 평가와 S09 전환 검증은 아직 미실행이다.
