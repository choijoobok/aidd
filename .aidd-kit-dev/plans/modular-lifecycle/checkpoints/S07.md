# S07 — 브리핑·파생 문서·매뉴얼·제출물

APR-004의 S04~S07 연속 실행 범위를 완료했다. S08 이후는 시작하지 않는다. 이 체크포인트는 전체 Kit 출시 또는 전체 21개 요구의 최종 인수 완료를 뜻하지 않는다.

## 구현 결과

- 동일 evaluator를 사용하는 프로젝트/모듈/주기/작업 브리핑과 다음 조치, 미응답 질문 복원.
- ID별 JSON 정본에서 ID별 Markdown, 모듈 인덱스, 상태 JSON/Markdown, 기능·화면 명세, HTML 목업과 MAN 가이드 생성.
- 모듈별 출력 소유 manifest와 프로젝트 공통 내비게이션 분리. 전체 생성 뒤 부분 생성 가능, 다른 모듈/사용자 파일 보존, 수동 생성물 수정 충돌 감지.
- 대상 전체 파일 목록/내용/manifest 해시 재계산 비교. 오프라인 목차·검색·인쇄·테마·글자 크기 제공.
- DLP 기반 설계/사용자/운영/용어집 조립. 사용자 공개 경계와 실제 캡처/목업 구분, 기존 출력 덮어쓰기 금지.
- 최종 교차 점검에서 high-level operation 재시도, CLI 옵션·종료 코드, 128개 단위 type index paging, 독립 모듈 index 재생성, 실제 두 writer 경합과 훅 보호 경계를 추가 확인했다.

## 검증과 한계

최신 전체 회귀 60/60, Kit check, generation/export/new-project smoke, hook self-test와 provider 동기화가 통과했다. 최종 교차 확인에는 명시적 사용자 동등성 재사용과 범위/입력/만료/정책에 한정된 EXC를 포함했다.

최신 전체 테스트·Kit check/smoke 결과는 status.json.validation이 정본이다. 최초 전체 회귀 56/56 뒤 paging 및 owned-hooks 시험을 추가했다. 기존 v1 reference fixture의 전체 생성 결과 비교는 유지한다. 새 v2는 테스트의 명시적 modular-fixture와 임시 작업공간에서 검증한다.

skill-creator의 Python quick_validate는 로컬 PyYAML 부재로 실행되지 않았다. 의존성을 추가 설치하지 않았다. 기존 frontmatter를 보존했고, Kit 구조 검사·provider 바이트 일치 검사와 본문 참조 검사로 대체했다. 실제 provider의 프로젝트 수행 능력을 이 검사로 주장하지 않는다.

## 다음 단계 인계

1. S08: 전체 기존 명령·스킬/참조/훅의 v2 전수 통합과 실제 provider 수행 평가. 현재 일부 전문 명령(term-review/apply, merge/evaluation/history 등)은 명시적 not_implemented로 안전하게 거부하며 기존 v1 writer로 넘어가지 않는다. record-put과 review-record로 보존되는 새 정본 경로와 전문 UX 연결을 마무리해야 한다.
2. S08 정책 통합: 구현된 EXC/동등성 계약을 관련 전문 스킬·프로젝트 정책에 전수 연결한다. EXC는 명시적 정책/현재 해시/보완 통제/평가 시각·만료가 있어야 제한된 기준에만 적용하고, 사용자 요구 승인은 면제하지 않는다. 동등성은 이전/현재 해시·입력·사용자 수용을 갖춘 RVW로만 재사용한다. 자동 오탈자 면제는 없다.
3. S09: 공식 v1 입력의 별도 후보 변환·ID/이력 보존·실제 export/new-project 전체 시나리오와 rollback 한계 검증. 실제 사용자 프로젝트는 이번에 변환하지 않았다.
4. S10: 최종 21개 요구·63개 AC·22개 시나리오 전체 인수, 브라우저별 시각/접근성·실제 사용자 화면 수용과 릴리스 준비도 보고.
