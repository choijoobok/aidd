# AIDD 아키텍처

제품 접속·권한 설계에는 [선행 접근 정책](../../../.ai/spec/system-access.md)을 읽는다. 현재 사용자 검토를 받은 POL과 ACT/UC 규칙을 요구→FEAT→SCR/NAV·TC로 연결한다. 최초/인증 후 화면과 거부·만료·회수·직접 접근·데이터 범위를 상세화하고, 미정 정책을 기술 선택으로 대신 확정하지 않는다. 변경 발견 시 해당 정책으로 돌아가 영향 분석과 필요한 재검토를 수행한다.

모듈별 정본 조회·전문 명령·게이트는 [v2 통합 계약](../../../.ai/spec/specialty-integration.md)을 적용한다. 현재 owner/CHG 범위를 먼저 고르고 공통 정의를 참조한다. 쓰기 명령에는 고유 operation을 사용하며 사용자 결정·현재 유효성·실제 실행을 구분한다.

v2에서는 `.ai/spec/business-discovery.md`의 선행 업무 정의와 요구 출처도 확인한다. SYS 목적·경계, ACT 목표, UC/BPR 인계·상태·예외가 미정이면 임의의 기능·화면으로 메우지 말고 해당 분석으로 돌아간다. CAP는 업무 능력, FEAT는 상세 기능이다. 메뉴는 역할별 흐름과 화면에서 구성하고 UC/기능과 일대일로 강제하지 않는다.

owned-records-v2에서는 `.ai/spec/owned-records-v2.md`의 기능·화면·개발·영향 계약을 먼저 읽는다. CHG 전체 요구가 현재 사용자 수용/기준선에 도달한 뒤 FEAT/SCR/DAT/NAV를 ID별 정본으로 작성한다. 기능·화면 설계와 현재 목업 출력의 사용자 검토를 분리한다. 변경 시 typed 영향 후보·경로를 확인하고 필요한 요구/설계/작업만 재개하며 운영 REL과 과거 증거를 보존한다. 미검토 목업을 실제 구현 또는 사용자 수용으로 보고하지 않는다.

1. 영향받는 요구사항, 모듈, 결정, 배포 프로필, 설계 위험, 변경 등급과 현재 코드·실행 증거를 읽는다.
2. 기술을 선택하기 전에 `DG-001`에서 배포 위치, 실행 플랫폼, DBMS, 인스턴스·확장 구조, 워크로드, SLO·RTO·RPO, 상태와 운영 제약을 확인하고 품질 속성·동시성 불변 조건을 확정한다.
3. `TG-001`에서 현행 유지를 포함한 기술 후보를 적합성, 역량, 지원 수명, 보안·공급망·라이선스, 데이터·규제, 테스트, 운영, 비용, 종속과 가역성으로 비교한다. C2·C3 또는 핵심 불확실성은 타임박스된 실험으로 검증한다.
4. 추천과 고객 결정을 분리한 ADR 초안을 만들고, 질문 전에 `aidd-decision-management`로 미결 OI를 만든 뒤 ADR 등 대상 ID를 연결한 DRQ를 저장한다. 고객 결정 뒤 버전·재검토 조건이 있는 기술 기준선을 확정하고 결정 주체와 이유를 ADR과 필요한 HIS에 기록하며 OI와 DRQ를 종료한다.
5. 모듈 경계, 소유권, `IFC` 인터페이스 계약, `DPN` 의존 방향·상태·검증, 실패 동작, 데이터 소유권·계보와 배포 구조를 정의한다. 설계 중 새롭거나 모호한 업무·제품·기술 용어가 나오거나 같은 이름이 다른 경계를 가리키면 `aidd-terminology` 스킬로 명확화와 프로젝트의 오프라인 결정 흐름을 수행한다. 트랜잭션과 외부 부작용, 프록시 기반 AOP 우회, 스레드·비동기 컨텍스트, 재시도·중복·순서 역전, 다중 인스턴스 경쟁과 스케줄 중복, 자원 포화와 의존 장애 전파를 적용 여부와 함께 검토한다.
6. `TG-002`에서 기능 규모의 UI 개발 전에 레이아웃, 내비게이션, 상태, 접근성, 디자인 토큰, 상호작용 패턴과 공통 컴포넌트를 정의한다. 기능 규모의 코드 개발 전에는 아키텍처 규칙, 오류 처리, 관측성, 테스트, 보안, 배포, 마이그레이션과 롤백 표준, 적용 위험별 경쟁·부하·장애 검증 및 대표 골든 패스를 준비한다.
7. 의미 있는 대안을 비교하고 맥락, 선택지, 결과, 롤백과 대체 관계가 있는 ADR을 작성하거나 갱신한다.
8. 기존 시스템 작업에서는 현행 기술 유지안을 기본 대안으로 포함하고 현재 동작을 기준선화한다. 코드·명세 충돌을 불일치로 기록하며 호환성, 마이그레이션, 롤백과 회귀 범위를 포함한다.
9. 관련된 보안, 개인정보, 데이터, DBA, 인프라, SRE, 운영과 감리 관점을 적용한다. 관점을 조용히 생략하지 말고 적용 대상이 아니면 이유를 기록한다.
10. 적용되는 `DG`·`TG`마다 변경별 `GTR` 실행을 만들고 기준별 `EVD` 또는 이유·만료·보완 통제가 있는 예외를 연결한다. 정본 아키텍처·기술 기준선과 추적 링크를 갱신하고 인계 전에 생성·검증한다.

설계 증거 체크리스트는 [references/design-checks.md](references/design-checks.md)를 읽는다. `STD`·`UXB`·`UIP`·`CMP`·`GPH`·`EXC` 기반을 설계하거나 변경할 때는 [references/development-foundation.md](references/development-foundation.md)를 함께 적용한다.
