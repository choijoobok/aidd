# 착수·단계 전환·변경 통제

## 착수

1. 저장소와 AIDD 정본의 존재 여부를 확인하고 읽기 전용 `project-init-status`, 범위별 `validate`를 실행한다. 초기화 요청일 때만 `project-init`을 실행한다. 협업 신원·권한 검사는 정본 요구 또는 사용자 요청이 있는 범위에서만 수행한다.
2. 제품 의도, 성과, 범위, 제외 범위, 배포 맥락과 결정권자를 확인한다.
   v2의 신규 업무는 SYS/CAP/ACT → UC ↔ BPR → REQ/NFR로 구체화하고 discovery-check로 선행 정의/사용자 검토를 확인한다. 기존 모듈은 관련 공통 정의를 재사용하며 같은 내용을 새 주기마다 복제하지 않는다.
3. 첫 `CHG`, 영향 모듈, 방법론 경로, 필수 게이트와 다음 고객 결정을 등록한다. 사용자에게 물을 결정은 질문 전에 `DRQ`로 저장한다.
4. 기술이나 구현 산출물이 먼저 존재하더라도 결정된 요구로 소급 포장하지 않고 기준선 또는 불일치로 기록한다.

## 단계 전환

정책 파일의 존재가 아니라 변경별 `GTR`의 기준, `EVD`, 통과 상태와 예외를 확인한다. 진입 조건과 종료 조건을 분리하고, 조건 미충족이면 현재 단계와 차단 사유를 유지한다.

## 변경 통제

변경은 현재 기준선 대비 `지금 수행`, `나중 수행`, `수행하지 않음`을 구분한다. 각 선택지의 범위 증감, 가치, 비용, 위험, 가역성과 재검토 조건을 제시하고 고객 결정을 기록한다. 작은 변경을 새 프로젝트처럼 재시작하지 않고 영향에 맞는 검증과 롤백 경로를 정한다. 독립 검토는 정본 요구 또는 사용자 요청이 있는 경우에 수행한다.

기존 미응답 DRQ가 있는데 사용자가 독립적인 다른 변경을 요청하면 해당 변경을 진행할 수 있다. 새 변경에도 결정이 필요하면 그 미결 대상을 먼저 정본에 기록하고 새 DRQ 묶음을 추가하며 기존 묶음을 덮어쓰지 않는다. 기존 결정이 현재 변경의 전제이거나 필수 게이트를 차단할 때는 관련 질문과 영향을 다시 제시한다.
