# KIT-REQ-018-011 — 지속적으로 관리하는 기능 상세 명세

- 출처: 사용자 기능 단위 설계·개발 요청 / 계획 목표 6~7, 15
- 목적: 요구사항에서 실제 동작 설계와 개발·검증까지 연결되는 기능 계약을 유지한다.
- 대상·트리거: 기능 도출, 상세 설계, 기능 재사용·수정, 구현과 테스트 계획.

## 요구 동작

- 기능은 안정된 ID, 소유 범위와 개정본을 가진 정본으로 관리한다. 변경 건마다 같은 기능을 새 기능으로 복제하지 않는다.
- 연결 요구·유즈케이스, 수행 주체, 선행/종료 조건, 정상 흐름, 업무 규칙, 입력/출력, 예외·경계, 데이터·외부 계약, 관련 화면, 관찰 가능한 테스트 연결을 적용성에 따라 상세화한다.
- 하나의 기능과 여러 화면, 하나의 화면과 여러 기능을 연결할 수 있다. 화면이 없는 API·배치·이벤트 기능도 독립적으로 설계·검토한다.
- 설계 중 새로운 업무 규칙·데이터 수집·권한 등 요구 변경을 발견하면 요구사항 검토로 되돌린다. 기능 명세에만 숨겨 사용자 요구 승인을 우회하지 않는다.
- 현재 기능 정본을 두지 않는 정책은 명시적으로 변경한다. S03에서 기존 REQ/UC/CHG/WRK/SCR과의 책임 분리, 이름·스키마와 호환성을 결정한다.

## 범위·관계

- 포함: 지속되는 기능 계약과 변경별 설계·개발 작업의 구분.
- 제외: 명칭만 바꾸어 기존 정책과의 충돌을 숨기는 것, 소스의 모든 함수·클래스를 기능 레코드로 만드는 것.
- 관계: 002~007, 012~014, 021.

## 인수 기준

- AC-011-1: 같은 기능을 두 변경 주기에서 수정해도 ID·소유 정본은 유지되고 각 변경 대상 개정본을 식별한다.
- AC-011-2: 다대다 화면 연결 기능과 비UI 기능 모두 적용되는 상세 계약·요구·테스트를 추적할 수 있다.
- AC-011-3: 설계 중 추가된 업무 요구가 미검토이면 그 기능의 개발 준비가 성립하지 않는다.
- 검증 연결: ACC-011.
