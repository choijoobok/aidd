# 산출물과 정본 모델

## 권위 순서

1. `.aidd/ssot/`에 기록한 고객 승인 의도와 의사결정.
2. `.aidd/ssot/`의 요구사항, 배포 프로필·설계 위험, 아키텍처, 기술 기준선·게이트, 방법론 정책, 모듈, 변경, 위험, 테스트와 릴리스 정본.
3. 스키마, API 명세, 마이그레이션, 테스트, 정책 코드 같은 실행 가능한 계약.
4. `docs/generated/`의 사람이 읽는 자동 생성 문서.
5. 구현과 실행 환경에서 수집한 증거.

하위 계층은 상위 계층에 부합해야 한다. 불일치가 발견되면 결정 또는 변경 레코드로 해결하며 어느 한쪽을 조용히 덮어쓰지 않는다.

## 안정적인 식별자

다음 접두사를 사용한다. `OUT` 성과, `REQ` 요구사항, `MOD` 모듈, `MLS` 마일스톤, `WRK` 작업, `IFC` 인터페이스, `DPN` 의존성, `ADR` 결정, `OI` 미결사항, `RSK` 위험, `CHG` 변경, `TC` 테스트 케이스, `REL` 릴리스, `MRG` 병합 영향, `DPP` 배포 정책, `DG` 배포 맥락 게이트, `DEP` 배포 프로필, `DIN` 환경 인터뷰 차원, `DPR` 설계 위험 패턴, `TSP` 기술 정책, `TG` 기술 게이트, `TSB` 기술 기준선, `GTR` 게이트 실행, `GCR` 게이트 판정 기준, `EVD` 검증 증거, `APR` 승인, `EVP` AI 평가 정책, `EVS` AI 평가 시나리오, `EVR` AI 평가 실행, `RGP` 저장소 거버넌스 정책, `CBG` 협업 거버넌스 정책, `CBP` 협업 프로필, `HUM` 사람 참여자, `CBT` 협업 전환, `IDP` 신원 대조 정책, `IDM` 신원 매핑, `IDE` 신원 변경 이벤트, `OPS` 운영 가이드, `USR` 사용자 가이드, `SEC` 보안 가이드, `MTP` 방법론 정책, `MTH` 방법론 비교 항목, `MPR` 적용 방법론 프로필. 제목이 바뀌어도 ID는 변경하지 않는다.

## 작성 문서와 생성 문서

- 직접 작성: `.aidd/ssot/*.json`, 방법론 설명, 코드, 테스트, 다이어그램 코드와 운영 설정.
- 자동 생성: 요구사항 정의서, 배포·운영 맥락과 설계 위험, 아키텍처 뷰, 기술 스택·기반 게이트, 방법론 비교, 모듈 전달 계획, 운영자·사용자·보안 가이드, AI 행동 평가, 협업 운영 프로필, 저장소 보호 정책, 추적성 매트릭스, 결정 기록, 미결사항 목록, 테스트 결과서, 릴리스 준비도와 상태 브리핑.
- 자동 생성 파일에는 원본을 표시하고 사람이 직접 수정하지 않는다.

## 일관성 불변 조건

- 모든 요구사항은 존재하는 모듈과 테스트 케이스를 참조한다.
- 모든 모듈은 존재하는 요구사항만 나열하며 양방향 참조가 일치한다.
- 구현 또는 인수 완료된 요구사항에는 통과한 검증 증거가 있다.
- 승인된 결정에는 결과와 롤백 또는 대체 경로가 있다.
- 기술 스택 선정과 개발 기반 준비도 게이트에는 적용·진입·증거·종료·재평가 조건이 있다.
- 배포 맥락 게이트에는 설계를 바꾸는 환경 범주가 있고 각 설계 위험 패턴에는 질문·실패 방식·통제·검증이 있다.
- 방법론 비교 항목에는 적합한 상황, 강점, 한계, 채택 통제, AIDD 연결과 1차 근거가 있다.
- 종료된 미결사항에는 해결 내용과 연결된 결정 또는 변경이 있다.
- 릴리스는 존재하는 변경을 참조하며, 차단 미결사항·실패한 필수 테스트·수용되지 않은 치명적 위험이 있으면 준비 완료가 될 수 없다.
- Codex와 Claude 스킬 어댑터는 `.ai/skills/` 정본과 바이트 단위로 동일하다.
- 완료 작업은 요구사항·변경·모듈·인수 기준과 통과 증거에 연결되고, 작업·인터페이스·의존성 참조는 존재해야 한다.
- Codex·Claude 행동 동등성은 같은 평가 시나리오와 루브릭의 플랫폼별 실행 증거로 판단하며 파일 동등성으로 대체하지 않는다.
- 저장소 보호의 로컬 구성과 원격 활성화 상태를 구분한다.
- 활성 사람 참여자가 1명이면 1인 협업 프로필, 2명 이상이면 팀 협업 프로필이어야 하며 전환 이력을 보존한다.
- 1인 프로필은 다른 사람의 승인을 필수화하지 않되 C2·C3 독립 보증 증거를 요구하고, 팀 프로필은 작성자 외 사람 승인을 요구한다.
- Git 이름·이메일과 호스팅 계정은 사람 참여자 또는 봇에 중복 없이 연결하며, 미등록 신원을 근거로 참여자를 자동 생성하지 않는다.
- 미등록 Git 신원은 C2·C3 개발 진입과 릴리스를 차단한다. Git 이력과 호스팅 제공자의 PR·승인·push 행위자 증거를 서로 대체하지 않는다.
- `AGENTS.md`와 `CLAUDE.md`는 `.ai/core/agent-contract.md`와 바이트 단위로 동일하다.

`python tools/aidd.py validate`는 기계적으로 확인 가능한 조건을 검사한다. 의미 품질은 검토 게이트에서 확인한다.
