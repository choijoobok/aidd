# AIDD 사용자 가이드

1. 대상 독자, 릴리스, 모듈, `MAN/SCR`, 관련 요구사항과 제출 정책 `DLP`를 확인한다.
2. `MAN`의 사전 조건, 단계, 예상 결과, 권한, 오류 복구와 지원 경로가 실제 동작·테스트와 일치하는지 검토한다.
3. 설계 검토본은 명시적으로 표시된 목업을 사용할 수 있다. 출시본은 대상 커밋·환경·화면 ID를 가진 실제 캡처 `EVD` 또는 승인된 예외만 사용한다.
4. 정본에서 `project/docs/generated/manuals/**`와 사용자 HTML을 만들고 링크, 내비게이션, 접근성, 이미지 대체 텍스트와 오프라인 열람을 검사한다. 사용자 HTML 용어집에는 승인된 `customer` 공개 범위이면서 `end_user` 독자인 프로젝트 용어만 포함하고 내부 AIDD 약어는 노출하지 않는다.
5. 누락·불일치는 정본 또는 구현 결함으로 보고한다. 생성 사이트를 직접 수정하지 않는다.

프로젝트 공통 HTML 홈은 project.json의 소개·개요·목적·주요 기능을 사용한다. 사용자 매뉴얼 사이트에서도 홈 로고·프로젝트명은 이 공통 홈으로 연결하고, 실제 화면과 목업의 구분은 유지한다. 사용자 사이트는 업무·화면 안내를 트리 목차와 본문 검색으로 열람하는 파생 HTML이며, MAN 정본과 검증된 화면 증거를 갱신한 후 다시 생성한다.
