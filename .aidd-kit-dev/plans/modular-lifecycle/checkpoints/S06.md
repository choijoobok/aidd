# S06 — 기능·화면·목업·개발·선택적 복귀

APR-004에 따라 완료하고 S07로 진행한다.

- FEAT/SCR 상세·검토와 현재 목업 input/output hash, 상태·뷰포트 검토를 WRK 개발 준비에 연결했다.
- HTML 목업은 실제 입력 유효성, 시나리오 선택, 상태 전이와 키보드 기본 컨트롤을 갖는다. 생성 자동 검사와 사용자 화면 이해 검토는 별개다.
- 동일 CHG의 W1 준비/W2 미준비, 비UI 경로, contract/implementation/integration 선행 출력 구분을 구현했다.
- typed 역관계 전파·selector·순환·unknown coverage와 명시적 IMP 분류/선택 WRK 재개를 연결했다.
- 수동 completed·stub 통합·오래된 게이트 우회를 차단하고 실제 AC/작업/통합 증거와 필수 최신 게이트를 요구한다.

## 검증

design-impact 8/8: UI/API 작업 준비, 실제 생성 script의 입력 검사/상태 전이, placeholder/변경 검토 무효화, 의존 출력, transitive/cycle/selector, stub 차단, 실제 파일의 선택 재개/운영 이력 보존, 실제 증거+GTR의 릴리스 준비 전체 흐름. lifecycle operations 회귀 1/1. provider 동기화·Kit check/smoke는 status.json에 최신 결과를 기록한다.

목업 자동 행위는 Node VM의 DOM 시험 대역으로 검증했다. 실제 사용자 화면 수용·브라우저별 접근성 평가·provider 실제 프로젝트 수행은 이 결과에 포함하지 않는다. 실행한 release-check는 배포/운영 기준선 변경이 아니다.
