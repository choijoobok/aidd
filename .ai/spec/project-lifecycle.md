# 프로젝트 수행 생명주기

프로젝트 수행 생명주기는 루트 `AGENTS.md`와 `.ai/skills/`의 계약을 따른다. 제품 정본은 `project/.aidd/ssot/`, 파생 문서는 `project/docs/generated/`, 제품 소스는 `project/src/`에 둔다.

수행팀은 의도·성과·범위 합의, `BEN-TRIAGE` 벤치마킹 필요성 판단, 필요한 경우 고객과 합의한 범위·기준의 외부 조사와 추천·결정, 요구·설계·표면 문서화, 위험 비례 게이트, 작은 구현 증분, 검증 증거, 출시·운영의 순서로 일한다. 벤치마킹 필요성 판단은 필수지만 외부 조사는 자동 또는 무조건 수행하지 않는다. 조사 관측은 보조 `research-note`에 출처·한계·우리 환경과의 차이를 남기며 고객이 수용한 내용만 ADR·REQ·OI에 반영한다. 배포된 Kit 파일도 프로젝트 상황에 맞게 바꿀 수 있지만, 변경 이유와 영향·검증 결과를 프로젝트 정본에 기록한다.

요구분석부터 공통 AIDD 용어는 `.ai/manifests/terminology.json`의 뜻을 그대로 사용하고, 업무 개념은 프로젝트 `terminology.json`에 제안한다. 새 용어 또는 의미 변경은 `term-propose` → `term-impact` → 사용자 `term-decide` → 영향 반영 후 `term-close` 순서로 처리한다. 영향 검토는 요구사항·모듈·설계·데이터·API·화면·테스트·문서의 후보를 기록하며, 승인 전에는 확정 용어처럼 사용하지 않는다. 승인된 영향의 반영 종료 이력이 생긴 뒤 생성기와 훅이 통합 Markdown 및 독자별 오프라인 HTML 용어집을 현행화하고 `validate`로 정합성을 확인한다.

Kit 원본의 변경을 발견했다고 해서 프로젝트에 자동 적용하지 않는다. 반대로 프로젝트의 개선을 원본에 코드로 자동 반영하지 않는다. 필요한 경우 변경 정보를 검토하고 각 환경에서 별도 변경으로 구현한다.
