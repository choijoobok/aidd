# KIT-REQ-018-008 — 정본 소유권과 의미 단위 파일 분리

- 출처: 사용자 의도 — 모듈별 정본 분리와 파일 대형화 방지 / 계획 목표 10~11
- 목적: 모듈의 일을 이해·변경할 때 필요한 정보만 찾고 수정하게 한다.
- 대상·트리거: 정본 추가·분할·이동·공통화.

## 요구 동작

- 독립적으로 검토·변경하는 요구·기능·화면·계약·결정·작업·테스트 등은 작은 레코드 단위로 관리한다.
- 각 정본에 하나의 소유 모듈 또는 공통 소유 범위를 두고 다른 소비자는 ID로 참조한다. 위치를 옮기거나 이름이 바뀌어도 ID를 바꾸지 않는다.
- 데이터 속성·화면 입력 항목처럼 함께 검토하는 하위 요소는 의미 단위로 묶을 수 있다. 큰 항목은 의미 있는 부분으로 분리하고 소유 관계를 보존한다.
- 파일 크기는 분할 검토의 신호이며 줄 수만으로 무의미하게 자르지 않는다. 구체적인 권고 크기와 표현 형식은 S03에서 정한다.
- 전체 공통 큐·범위 조회가 필요한 정보도 물리적 한 파일을 강제하지 않는다. 큰 실행 로그·미디어는 정본에서 참조한다.

## 범위·관계

- 포함: 전역 거대 파일의 모듈/공통 레코드 분리, 하위 요소의 안정 참조.
- 제외: 모든 속성의 무조건 개별 파일화, 같은 정본을 여러 모듈에 복제.
- 관계: 005, 009~010, 017, 020.

## 인수 기준

- AC-008-1: 모듈 A의 요구·설계·작업·테스트를 소유 경계로 찾을 수 있고 공통 계약은 단일 정본을 참조한다.
- AC-008-2: 같은 ID의 중복 소유 정본이 생기면 오류로 보고하고 어느 하나를 임의 선택하지 않는다.
- AC-008-3: 큰 레코드 분리·이동 후 기존 ID 참조와 승인 대상 의미가 보존되거나 명시적인 의미 변경으로 기록된다.
- 검증 연결: ACC-008.
