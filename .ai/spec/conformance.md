# 적합성 기준

AIDD 적합성 검증은 사용자가 요청한 요건과 스펙이 규칙·스킬·훅·도구에 실제로 구현되었는지를 빠르게 확인하기 위한 것이다. 검증 절차 자체를 제품 요구사항보다 크게 만들지 않는다.

## 기본 원칙

- 정본은 Kit의 `.ai/spec/`, `.ai/manifests/`, `AGENTS.md`와 프로젝트의 승인된 `project/.aidd/ssot/`다. fixture, 생성물, 과거 검증 기록은 정본이 아니다.
- 구조 검사만으로 구현 충실성을 단정하지 않는다. 요청 범위의 대표 정상·실패 입력으로 관찰 가능한 동작을 확인한다.
- 보안·권한·신원·서명 검사는 정본 요건에 명시되어 있고 검증 범위에 포함되거나 사용자가 별도로 요청한 경우에만 수행한다.
- 일상 검증은 빠른 구조 검사와 변경 영역 테스트로 끝낸다. 전체 fixture, 전체 테스트, export·new-project 검증은 영향을 받는 경우에만 실행한다.
- 검증 결과 때문에 별도 evidence 파일, 반복 재검토, 승인 게이트를 자동으로 만들지 않는다.

## Kit 원본

Kit 원본은 다음 경계를 만족해야 한다.

- `.aidd-role.json`은 `kit-source`이고 루트에 제품용 `project/`가 없다.
- portable 명세·스킬·훅·도구는 `.ai/`, Kit 관리 전용 파일은 `.aidd-kit-dev/`에 격리된다.
- export는 하나의 허용 목록으로 directory와 ZIP을 조립하고 `.aidd-kit-dev/`와 관리 전용 스킬을 포함하지 않는다.
- provider 스킬 복사본은 portable 스킬과 같고 provider 훅은 공통 훅 계약의 이벤트별 동작에 연결된다.
- 실행 도구와 훅은 Node.js 22 이상과 표준 라이브러리만 사용하며 훅 입력을 UTF-8로 처리한다.
- `new-project`는 `product-workspace` 역할과 유효한 `project/.aidd/ssot/`를 만든다.

## 훅

provider 훅은 세션 요약과 배선 self-test, 생성물 직접 수정 보호, 용어 정본 변경 뒤의 현행화, 선택 가능한 로컬 대화 로그를 제공한다. 훅은 AIDD 자체 승인, 세션 재시작, Git 서명, 외부 trust-root, 일반 shell 권한 검사를 강제하지 않는다. 훅 실패는 해당 자동화 실패만 간결하게 알리고 별도의 정책 승인을 만들지 않는다.

## 파생 문서

`generate`는 정본의 구조화된 내용을 결정적으로 파생하며 확인되지 않은 사실을 만들지 않는다. 파생 문서 검증은 현재 정본으로 임시 위치에 다시 생성한 결과와 비교해 다음을 모두 확인한다.

- 기대 파일이 모두 존재한다.
- 각 파일의 전체 내용이 현재 renderer 결과와 같다.
- 더 이상 생성 대상이 아닌 파일이 남아 있지 않다.
- 정본에 있는 요구사항·결정·절차·추적성 정보가 해당 독자용 문서에 누락되지 않는다.
- 독자별 DLP 필터가 명시된 경우 그 공개 경계를 지킨다.

공통·프로젝트 용어집도 같은 생성·비교 규칙을 따른다. proposed 용어는 분석 기록에만 허용하고 확정 계약·문서·제품 소스에는 사용하지 않는다.

## 실행 수준

- `kit.mjs check`: JSON, 필수 경계, provider 동기화와 훅 배선을 확인하는 빠른 검사다.
- 변경 영역 테스트: 해당 요건의 실제 정상·실패 동작만 확인한다.
- `kit.mjs smoke`: 생성기, fixture, export, new-project 또는 provider 경계가 영향을 받을 때만 대표 흐름과 파생 문서 전체 비교를 수행한다.

사용자가 AIDD 구현 검증을 요청하면 `aidd-requirement-verification` 스킬을 사용해 이 기준을 적용한다.
