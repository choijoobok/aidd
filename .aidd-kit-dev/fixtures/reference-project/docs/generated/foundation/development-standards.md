# 프로젝트 개발 표준

## STD-001 — 정본과 파생 산출물 관리

- 상태/유형: `최신` / `policy`
- 범위: 모든 프로젝트와 모듈
- 기술 기준선: TSB-001
- 모듈: MOD-GOV, MOD-DOC
- 요구사항: REQ-001, REQ-002, REQ-031
- 검증: TC-024

### 규칙

- project/.aidd/ssot의 구조화 레코드를 승인된 의도의 정본으로 취급한다.
- project/docs/generated와 제출 manifest는 정본에서 결정적으로 재생성한다.
- 코드와 정본의 불일치는 어느 한쪽을 몰래 우선하지 않고 변경 또는 결함으로 기록한다.

### 보장

- 사람과 AI가 동일한 승인 기록과 안정 ID를 참조한다.

### 보장하지 않는 것

- 문서 또는 훅의 존재만으로 실제 준수나 게이트 통과를 보장하지 않는다.

## STD-002 — 프로젝트별 개발 기반 작성

- 상태/유형: `template` / `policy`
- 범위: TG-002를 적용하는 제품 프로젝트
- 기술 기준선: TSB-001
- 모듈: MOD-ARCH, MOD-DELIVERY, MOD-QA
- 요구사항: REQ-011, REQ-031
- 검증: TC-024

### 규칙

- 기술 스택 선정 뒤 아키텍처, 보안, 테스트, 관측성, 배포와 운영 표준을 프로젝트 정본으로 작성한다.
- 실행 실패로 드러나는 contract와 조용히 위반될 수 있는 policy를 구분해 검증 방법을 정한다.
- 적용 가능한 표준에는 골든 패스 또는 실행 가능한 검증기를 연결한다.

### 보장

- 프로젝트별 기술 선택을 존중하면서 AI의 개발 절차와 품질 기준을 일관되게 전달한다.

### 보장하지 않는 것

- 이 템플릿은 특정 프레임워크, 언어 또는 UI 라이브러리를 선택하지 않는다.
