# 역분석 정본 작성 요구안

현재 구현은 일반 레거시 조사 스킬, LDP/SURF 기록, 문서화 WRK와 staged 문서 점검이다. 아래 요구는 추가 구현 대상이며 충족했다고 선언하지 않는다.

## RE-01 조사 범위와 원본 보호

사용자가 지정한 소스·문서·산출물 루트, 기준 커밋/파일 해시, 제외 범위와 작성 대상을 기록한다. Git 없는 자료와 여러 소스 루트를 허용한다. 원래 저장소 구조를 보존하며 project/src로 이동시키지 않는다. 경로 경계를 넘는 링크, 바이너리, 읽기 실패, 미지원 포맷, 제외 파일은 이유와 함께 구분한다. 읽을 수 없음을 기능 부재로 해석하지 않는다. 자료 조사만으로 제품 코드·스크립트 실행, 설치, 서비스 기동, 외부 전송을 허가받았다고 해석하지 않는다.

## RE-02 관측 사실·추론·결정의 구분

각 추출/초안 항목에 원본 위치(파일/심볼/행/문서 절/페이지 중 이용 가능한 것), 콘텐츠 해시, 수집 방법과 범위를 연결한다. 관측된 구조·동작, AI의 업무 해석, 미확정 사항, 모순, 사용자 결정을 구분한다. 신뢰 점수로 사용자 검토를 대체하지 않는다. 과거 문서·소스·테스트의 불일치에서 하나를 자동 정답으로 선택하지 않는다. 소스에 권한 검사가 안 보인다는 이유만으로 공개 기능이라고 확정하지 않는다.

출처 변경은 근거의 재확인 필요와 의미 변경 가능성을 구분한다. 줄 번호만으로 동일성을 판단하지 않고 해시·앵커와 대상을 함께 사용한다. 원문 전체를 정본마다 복제하지 않으며 원문/첨부의 제공·보존 범위는 사용자 지정에 따른다.

## RE-03 자동 작성 수준

도구의 재현 가능한 수집과 AI의 의미 분석을 결합한다. 아래 생성 결과는 사용자 검토 전 모두 초안이다.

| 수준 | 자동 지원 | 확정하지 않는 것 |
|---|---|---|
| 자료 인벤토리 | 파일·해시·소스/문서 분류·처리 여부·관측 출처 | 미조사 범위의 완전성 |
| 구조 추출 | 근거가 있는 화면/라우트·API·작업·이벤트·연동·테이블/속성 후보 | 실행 도달성·업무 의미·실제 성능/보안 |
| 의미 초안 | 모듈 경계, SYS/CAP/ACT/POL/UC/BPR 및 REQ/NFR·기능/화면/데이터/메뉴/연동 후보와 연결 | 업무 목적·정책·우선순위·목표 품질·사용자 의도 |
| 문서 생성 | 정본 초안에서 인덱스·명세·흐름도·검토 자료 생성 | 사용자 승인·테스트 통과·운영/출시 완료 |

미확인 필드는 unknown으로 남기고, 단순 상투 문구로 필수 항목을 채우지 않는다. 표면 하나당 요구·기능·유즈케이스를 무조건 하나씩 만들지 않는다. 하나의 업무가 여러 화면/API에 걸치거나 여러 역할·모듈을 가로지르는 관계를 허용한다. 이견이 있는 분류는 후보와 질문으로 남긴다.

첫 범용 버전은 파일 인벤토리/해시와 사용 가능한 텍스트·구조화 자료의 출처 계약, AI가 작성한 구조화 관측 입력의 검증/초안 생성을 지원한다. 모든 프로그래밍 언어·PDF/Office·이미지에서 자동 의미 추출을 보장하지 않는다. 별도 추출 수단이 없는 입력은 미처리로 표시한다. 전용 파서와 AI 해석의 산출 방법도 구분한다.

## RE-04 현재 상태와 목표 상태

현재 관측된 구현은 현행 상태로 보존한다. 그 동작을 유지할지, 결함으로 고칠지, 개선할지, 폐기할지는 사용자 검토로 결정한다. 새 요구에 맞지 않는 기존 코드도 조사 기록에서 지우지 않는다. 채택된 목표와 실제 구현 차이는 연결된 CHG/WRK로 추적하고 완료로 만들지 않는다. 분석 관측을 구현/테스트 EVD 또는 과거 사용자 승인으로 자동 변환하지 않는다.

## RE-05 사용자 검토와 부족 항목 채우기

시스템 개요·핵심 업무 → 역할·접속/인증/접근 정책 → UC/프로세스 → 요구·인수 기준 → 기능·화면·데이터·메뉴·연동 순으로 검토한다. 전체 초안은 미리 생성 가능하지만 검토 순서와 진입 게이트는 유지한다. 앞 단계 수정은 뒤 단계의 영향 대상만 재검토한다.

검토 묶음에는 현재 설명, 근거, 추론/미정/모순, 관련 항목, 사용자에게 필요한 선택을 함께 보여준다. 동일한 결정의 동종 항목은 묶음 검토하되 부분 승인/보류는 항목별 현재 해시에 적용한다. JSON 파일을 하나씩 수동 작성하게 만들거나 모든 항목을 한 번에 묻지 않는다. OI/DRQ와 기존 RVW를 사용한다.

## RE-06 안전한 초안 저장과 재분석

초안은 모듈/공통·유형·ID별로 저장하고 기존 인덱스로 탐색한다. 최초 생성 전에 생성/갱신 대상과 미확인 목록을 보여줄 수 있어야 하며 저장은 사용자 지정 범위 안에서만 한다. 재실행은 동일 관측의 중복 ID를 만들지 않는다. 이동/이름 변경의 매핑이 모호하면 확인 대상으로 남긴다.

마지막 생성본·현재 사용자 수정본·새 관측 초안을 비교한다. 사용자 수정·승인 내용을 새 분석 결과로 조용히 덮어쓰지 않는다. 변경 제안과 충돌, 없어졌을 가능성이 있는 항목을 구분하고 명시적 채택으로 반영한다. 불완전 스캔이나 원본 누락으로 정본을 자동 삭제/폐기하지 않는다. operation/CAS/복구를 유지하며 source→정본→검토→작업의 영향 경로를 표시한다.

## RE-07 모듈별 도입과 운영 지속

운영 모듈과 도입 분석 중인 모듈을 구분한다. 선택한 모듈/업무 범위의 근거·정의·사용자 검토·연결·검증 계획을 먼저 완성해 채택하고 다른 모듈은 계속 보완할 수 있다. 공통 정책·횡단 계약의 관련 의존 조건은 확인하되 전체 시스템의 미래 분석 완료를 기다리는 전역 장벽을 만들지 않는다.

기존 시스템이 동작한다는 사실과 현재 AIDD 요구를 검증했다는 사실을 구분한다. 문서 관리 도입 준비도, 대표 동작/회귀 검증 상태, 운영/릴리스 상태를 각각 보고한다. 과거 개발 전에 존재하지 않았던 목업 승인이나 테스트 실행 기록을 소급 조작하지 않는다. 기존 UI의 사용자 검토와 재사용 근거는 별도 확인하고 신규 UI 변경에는 정상 설계/목업 게이트를 적용한다.

## RE-08 진행 상황과 완료 기준

범위 대비 파일 처리/제외/미지원·관측 표면·출처 연결·미정·모순·사용자 검토·대표 동작 검증 건수를 분리해 보여준다. 문서 수나 파일 스캔 비율을 프로젝트 전체 완료율로 표현하지 않는다. 실제 읽지 않은 파일/실행하지 않은 테스트/미검토 정책은 완료로 표시하지 않는다.

채택 후 신규 기능·변경은 기존 AIDD CHG/WRK/RVW/BSL/IMP 흐름을 사용한다. 병렬 정본·영구 이중 관리 체계를 만들지 않는다. 자료 근거는 보존하되 정본에 대한 편집 책임은 하나로 유지한다.
