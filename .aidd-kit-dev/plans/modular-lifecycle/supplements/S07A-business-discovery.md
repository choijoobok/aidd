# S07A — 시스템·업무 분석 앞단 보완

## 승인·실패·범위

APR-005: 사용자는 앞선 분석에 따라 부족한 앞부분의 추가 보완 실행을 승인했다. 시스템 개요 → 핵심 업무 → 사용자 역할 → 유즈케이스 ↔ 프로세스 → 요구 → 분석 목록의 연결을 보완한다. S08~S10, 실제 프로젝트 전환, 커밋·릴리스는 포함하지 않는다. S02/S03 승인 파일과 해시는 보존하고 이 추가 명세로 차이를 관리한다.

현재 실패는 작성된 요구의 상세화만 검사하고, 요구를 충분히 발굴한 근거를 검사하지 않는 것이다. UC 유형은 존재하지만 상세 계약·완료 조건이 없다. 본 작업은 portable 계약·CLI·생성기·기존 스킬을 확장하며 런타임 훅을 추가하거나 배선을 변경하지 않는다.

## 추가 요구와 인수 조건

- BD-01: SYS(시스템 개요), CAP(핵심 업무 능력), ACT(업무 사용자/외부/자동 주체), UC, BPR(업무 프로세스)을 기존 owner/type/ID 구조로 분리한다. ACT는 수행팀 명부·인증 계정이 아니다. 초안 저장은 허용하고 불완전한 정의로 완료하지 않는다.
- BD-02: CHG의 명시적 discovery 범위로 조회·검토한다. 공통 정본은 참조하고 새 모듈의 독립 주기는 무관한 미래 모듈 때문에 차단하지 않는다. 비적용·제외·보류에는 사유와 현재 범위 사용자 검토가 필요하다.
- BD-03: 시스템/역할 검토와 유즈케이스/프로세스 검토를 현재 개정별로 기록한다. 묶음 검토와 개별 부분 응답을 모두 수용하되 미응답 항목은 통과하지 않는다. 초안 병행 작성은 허용하지만 요구 확정·설계 진입은 선행 분석 준비도를 포함한다.
- BD-04: 핵심 업무·역할 목표·UC 흐름·시스템 프로세스 단계의 누락을 검사한다. 수작업·외부 작업은 명시적으로 분류한다. 요구는 UC/프로세스 또는 시스템·정책·외부 계약 등 명시적 근거를 가지며 NFR에 가짜 UC를 강제하지 않는다.
- BD-05: 역할/업무/단계 변경이 요구·기능·화면·테스트까지 전파된다. 단계 안정 key를 사용하고 삭제/잘못된 selector를 탐지한다. 현재 검토 유효성과 과거 승인·출시 이력은 구분한다.
- BD-06: BPR의 단계/전이에서 오프라인 흐름도와 명세를 생성한다. 정본과 별도 수동 도식 정본은 만들지 않는다. 브리핑은 업무 분석과 요구 준비도를 별도로 보여준다.
- BD-07: 새 규칙은 기존 v2의 근거 없는 승인을 현재 완료로 간주하지 않는다. 원문/ID/RVW/BSL을 자동 수정하지 않고 보완 대상을 보고한다. v1 변환은 S09에서 별도로 수행한다.

## 구현·검증 계획

1. 계약/관계/범위·검토·기준선과 요구 출처 검사를 확장한다.
2. 저장·조회·영향 그래프, discovery-check CLI와 브리핑을 연결한다.
3. 프로세스 구조에서 Markdown/SVG/오프라인 문서와 공통 인덱스를 생성한다.
4. discovery/lifecycle/architecture/status 스킬과 가이드·manifest/schema를 갱신하고 provider를 동기화한다.
5. 정상 전체 흐름, 앞단 누락, 잘못된 타입/참조/단계, 부분 승인, 변경 후 stale, 비UI·NFR, 다른 모듈 재사용, 흐름도 재생성/수동 변경 보호를 회귀 검증한다. 기존 전체 테스트와 check/smoke/self-test를 실행한다.

완료 결과·잔여 제한은 checkpoints/S07A.md와 status.json에 기록한다. 승인된 S02/S03 문서를 재작성하지 않는다. 본 변경만 선택적으로 되돌릴 수 있지만 새 정본을 삭제하거나 구형 검토를 자동 승격시키는 롤백은 하지 않는다. 같은 owned-records-v2 저장 형식을 확장하므로 전체 KIT-CHG-018의 major 영향도를 유지한다.
