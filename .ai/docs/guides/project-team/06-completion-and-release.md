# 완료와 출시

## 변경 완료 조건

변경은 코드가 작성되었다는 이유만으로 완료되지 않는다. 적용 범위에 따라 다음을 확인한다.

- 연결 요구사항과 인수 기준을 충족했는가
- 결정, 인터페이스, 데이터와 운영 영향이 현행인가
- 관련 테스트가 실제 변경을 확인했고 결과가 기록되었는가
- 정본과 생성 문서가 일치하는가
- 사용자·운영·지원 문서가 필요한 독자에게 충분한가
- 마이그레이션, 호환성, 롤백과 잔여 위험이 설명되었는가
- 필수 게이트와 병합 후 재검토가 남아 있지 않은가

검증은 위험에 비례한다. 기본은 `validate`와 변경 영역 테스트이며, 전체 회귀·성능·보안·권한 테스트는 요구사항, 변경 영향 또는 사용자 요청이 있을 때 추가한다.

## 파생 문서 확인

```powershell
node .ai/tools/aidd.mjs document-impact --path project/.aidd/ssot/modules/MOD-CORE/REQ/REQ-001.json
node .ai/tools/aidd.mjs generate
node .ai/tools/aidd.mjs validate
```

파생 문서의 신뢰성은 현재 정본으로 다시 생성한 전체 파일 집합과 내용이 일치하는지로 확인한다. 생성 문서를 직접 고쳐 맞추지 않는다.

## 사용자·운영 산출물

사용자 가이드는 `MAN`과 `SCR`, 결정되고 검증된 제품 동작과 검증된 화면 자료에 기반한다. 설계 목업을 실제 화면으로 표시하지 않는다. 운영 런북은 선행 조건, 단계, 확인, 롤백과 에스컬레이션을 포함한다.

`DLP`가 정의된 경우 대상 독자, 포함·제외, 공개 용어, 실제 캡처 요구와 패키지 형식을 따른다. 조립된 사이트·ZIP·manifest는 재현 가능한 제출물이며 제품 정본이 아니다.

## 출시 준비 확인

```powershell
node .ai/tools/aidd.mjs integration-status
node .ai/tools/aidd.mjs release-check --release REL-001
```

다음이 남아 있으면 출시 준비 완료로 선언하지 않는다.

- 미통과 필수 게이트 또는 필수 예외 만료
- 출시를 차단하는 위험이나 `MRC`
- 확인되지 않은 마이그레이션·롤백 절차
- 오래되거나 누락된 생성 문서
- 대상 환경에서 확인하지 않은 필수 테스트

`release-check`는 정본의 준비 조건을 검사한다. 실제 배포, 외부 운영 결정, 계정 권한이나 운영 변경을 대신 수행하지 않는다.

## 출시 후

배포 결과, 장애와 사용자 피드백을 해당 릴리스·요구·변경·런북에 연결한다. 긴급 수정도 확인되지 않은 보안 요구나 광범위 검사를 자동으로 추가하지 않고, 실제 영향과 최소 안전 변경을 기록한다.

문제가 생기면 이전 기록을 삭제하기보다 새 변경과 대체 결정, 롤백 결과를 남긴다. 운영에서 얻은 사실은 다음 계획의 입력이 되고, 정본과 문서는 같은 증분에서 현행화한다.

## AI에게 요청하는 예시

> 이 변경의 완료 여부를 정본에서 확인해줘. 요구사항·작업·테스트·문서·운영 영향과 필수 게이트를 연결해 보고하고, 확인하지 않은 항목은 검증하지 않음으로 구분해줘.

> 이 릴리스가 준비됐는지 확인해줘. 전체 테스트를 임의로 돌리지 말고 변경 영향에 맞는 검사와 release-check를 실행해. 사용자·운영 문서와 롤백, 미결 위험도 함께 보여줘.

> 파생 문서가 현재 정본을 빠짐없이 반영하는지 검증해줘. 임시 위치에 다시 생성한 전체 결과와 비교하고 생성 문서를 직접 수정하지 마.
