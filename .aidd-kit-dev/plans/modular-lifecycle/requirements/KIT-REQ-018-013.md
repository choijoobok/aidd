# KIT-REQ-018-013 — 작업별 개발 진입과 선행 결과

- 출처: 사용자 기능·화면 단위 개발 요청 / 계획 목표 3, 7, 14
- 목적: 주기 전체 요구 검토를 마친 뒤 준비된 작업을 순차·병렬로 개발한다.
- 대상·트리거: WRK 개발 착수·재개와 선행 작업 결과 변경.

## 요구 동작

- 작업의 개발 준비는 유효한 해당 주기 요구 기준선, 적용 공통 기준선, 연결 기능 상세 명세, UI 작업의 화면 명세·목업 검토, 인수 테스트 계획과 선행 결과로 판정한다.
- 모든 설계 작업이 완료될 때까지 무조건 기다리지 않는다. 독립적인 작업은 해당 조건을 갖추면 개발할 수 있다. 다만 주기 요구 검토를 미완성 요구의 임의 제외로 통과시키지 않는다.
- 선행 의존은 계약 합의가 필요한지, 실제 구현 결과가 필요한지, 통합 검증이 필요한지 구분한다. 후자의 결과가 필요한 작업을 선행 WRK의 이름·상태 문자열만으로 허용하지 않는다.
- 개발 전에는 테스트의 입력·예상 결과·추적성이 준비되어야 한다. 아직 개발하지 않은 기능의 테스트 통과나 실제 화면 증거를 선행 조건으로 요구하지 않는다.
- 기반 코드 작업과 타당성 실험도 목적·범위·적용 계약을 명시한다. 실험 결과는 제품 개발·인수 완료로 승격하지 않으며 미승인 업무 기능을 실험으로 위장하지 않는다.

## 범위·관계

- 포함: 작업별 조건의 도출과 차단 사유, 준비된 작업부터 수행하는 유연성.
- 제외: 미결 의존을 숨기기 위해 작업 연결을 삭제하거나 모든 후속 구현을 개발 착수 전에 완료시키는 순환 조건.
- 관계: 002, 007, 011~012, 014~016, 021.

## 인수 기준

- AC-013-1: 같은 주기에서 설계가 준비된 W1은 개발할 수 있고 미검토 화면을 가진 W2는 차단 이유가 표시된다.
- AC-013-2: 실제 결과가 필요한 선행 WRK가 blocked이면 후속 개발을 차단하고, 계약만 필요한 경우에는 합의된 계약으로 진행 가능하다.
- AC-013-3: 테스트 계획 미비·누락된 관련 기능은 준비 실패가 되며, 구현 전 테스트 미실행 자체는 개발 착수를 막지 않는다.
- 검증 연결: ACC-013.
