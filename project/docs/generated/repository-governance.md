# 저장소 보호와 CI 정책

- 플랫폼: GitHub
- 기본 브랜치: `main`
- 상태: `차단됨`
- 협업 프로필: `CBP-SOLO 1인 프로젝트`
- 워크플로: `.github/workflows/aidd.yml`
- 규칙 구성: `.github/rulesets/main.json`
- 필수 상태 검사: 정본·문서·스킬·테스트 검증
- 원격 확인: 2026-09-18T01:25:44+09:00 · 실패 · GitHub API가 비공개 저장소의 ruleset 기능에 GitHub Pro 업그레이드 또는 공개 저장소 전환이 필요하다는 HTTP 403을 반환했다. · 증거 EVD-018

## 보호 규칙

- 직접 삭제와 강제 푸시 금지
- Pull Request를 통한 변경
- 활성 협업 프로필에 따른 사람 승인 수 적용
- 팀 프로필에서는 작업 브랜치에서만 커밋
- 검토 대화 해결
- 최신 main 기준의 필수 AIDD 검사 통과

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| GitHub Pro 업그레이드 | 비공개 상태를 유지하면서 ruleset을 적용한다 / 현재 원격과 CI를 그대로 사용한다 | 지속 비용이 발생한다 |
| 공개 저장소 전환 | 추가 요금 없이 ruleset을 사용할 수 있다 | 소스와 프로젝트 기록이 공개되며 민감정보 검토가 선행되어야 한다 |
| 다른 보호 기능 또는 호스팅 사용 | 조직 정책과 비용에 맞는 강제 통제를 선택할 수 있다 | 마이그레이션과 새 CI 어댑터 검증이 필요하다 |
| 현재 비공개 저장소 유지 | 즉시 비용과 이전 작업이 없다 | 원격 병합 강제가 없어 로컬 훅과 자발적 CI 준수에 의존한다 |

## 활성화 절차

규칙 파일을 GitHub Rulesets API 또는 저장소 설정에 적용한 뒤 원격 조회 결과를 EVD 증거로 기록한다. 로컬 파일 존재만으로 원격 보호가 활성화되었다고 판정하지 않는다.
