## 반영한 결과

1. SYS/CAP/ACT/UC/BPR를 기존 소유자·타입·ID별 정본에 통합했다. 시스템 공통 정의, 역할 목표, UC 정상/대안/예외 흐름, 프로세스의 사람/시스템/외부/하위 작업과 전이·데이터 상태를 명시한다. ACT는 수행팀 인증·권한 관리가 아니다.
2. CHG.discovery 범위, intent/business_flow 사용자 검토, BG-001/discovery-check와 요구 발굴 근거/단계별 포괄성 검사를 추가했다. 초안 저장은 허용하지만 미정·누락·미검토를 설계 준비 완료로 취급하지 않는다. 품질 요구에는 가짜 UC를 강제하지 않는다.
3. requirements BSL에 선행 업무 정의도 포함하고 공통/모듈의 묶음 검토 저장을 지원한다. 유효한 공통 검토 재사용과 변경 후 stale 판정을 분리한다. 기존 ID·승인·기준선·출시 기록은 삭제/소급 수정하지 않는다.
4. 역할·UC·프로세스 단계의 참조를 조회·입력 해시·영향 그래프에 연결했다. 기존 IMP의 명시적 선택 재개를 유지한다.
5. BPR 정본에서 오프라인 SVG·전이 조건 명세, 공통 인덱스·SYS 기반 홈·내부 설계 제출을 생성한다. status.discovery는 같은 판정 결과를 보여준다. 공통 프로세스 링크는 다른 모듈의 본문을 모두 읽지 않아도 동일하게 생성한다.
6. 기존 discovery/lifecycle/architecture/status 스킬과 관련 참조·프로젝트 가이드, 공개 manifest/schema를 갱신하고 provider 복사본을 동기화했다. 스킬 지침은 업무 이해를 기술 질문보다 먼저 수행하고 현재 검토에 따라 전환하도록 보완했다. 새 스킬·런타임 훅·등록 배선은 추가하지 않았다.

## 한계·후속 범위

- 구조·연결·현재 검토를 검사한다. 실제 업무의 완전성/의미 모순 없음, 실제 고객의 수용을 자동 증명하지 않는다. 테스트의 사용자 검토는 명시적 fixture다.
- 흐름도는 구조화된 프로세스의 정적 파생물이며 BPMN 실행/병렬 합류 의미 검증 엔진이 아니다. 자동 생성·내용/참조 일관성은 시험했으나 실제 브라우저의 시각·접근성 검토와 실제 provider 수행 평가는 미실행이다.
- 판정기 버전은 owned-readiness-2.1-business다. 이전 v2 input_digest나 UC 형식은 새 준비 조건을 충족한다고 자동 간주하지 않는다. 저장된 원문/ID/이력은 보존하고 부족한 항목과 재검토를 별도 처리한다. 구형 v1 후보 변환은 S09의 미완료 범위다.
- 전체 스킬·전문 명령/provider 통합 S08, 명시적 전환 S09, 최종 인수 S10은 남아 있다. 이번에 실제 프로젝트 마이그레이션·커밋·릴리스·배포를 하지 않았다.
