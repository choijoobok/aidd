# AIDD UI 명세

1. 영향 모듈, `REQ`, `UC`, 현재 유효한 `UXB/UIP/CMP`, 기술 기준선과 변경 등급을 확인한다.
2. 화면마다 안정적인 `SCR` ID, 모듈, 사용자·권한, 경로 또는 진입점, 정보 구조, 필드·행동, 로딩·빈 상태·오류·권한 상태, 접근성, 인수 테스트와 결정 상태를 JSON 정본에 기록한다.
3. 사용자 절차는 `MAN` ID, 대상 `SCR`, 독자, 사전 조건, 단계, 예상 결과, 오류 복구와 캡처 슬롯으로 분리한다. 구현 전 초안과 실제 화면으로 검증된 상태를 구분한다.
4. 공통 패턴과 컴포넌트는 복사하지 않고 안정 ID로 참조한다. 새 공통 후보는 `aidd-architecture`에서 트레이드오프와 영향 모듈을 검토한다.
5. 정본을 생성·검증하고 `project/docs/generated/ui/**`, `project/docs/generated/manuals/**`의 파생물을 확인한다. 파생 문서를 직접 수정하지 않는다.

기술 스택의 라우터·컴포넌트 라이브러리 문법은 프로젝트 `STD/GPH`가 정하며 이 스킬은 특정 구현을 강제하지 않는다.
