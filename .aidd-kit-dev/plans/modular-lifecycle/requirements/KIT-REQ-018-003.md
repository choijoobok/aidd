# KIT-REQ-018-003 — 요구사항 상세 항목과 적용성

- 출처: 사용자 의도 — 상세하고 명확한 요구사항 / 계획 목표 4~5
- 목적: 기술 설계를 시작할 수 있을 만큼 업무 결과·규칙·정보를 구체화한다.
- 대상·트리거: 요구사항 작성·변경·검토 준비 판정.

## 요구 동작

- 식별·출처·우선순위, 사용자/시스템과 가치, 범위/비목표, 트리거/선행조건/결과, 업무 규칙·금지 결과, 예외·경계, 데이터·속성, 접점, 품질·제약, 인수 기준, 관계·미결사항을 확인한다.
- 업무 특성별 적용 항목을 채운다. 미정, 해당 없음과 그 이유, 확정된 내용을 구분한다. 변경 등급이 낮다는 이유로 실제 필요한 계산·데이터·예외 규칙을 생략하지 않는다.
- 인수 기준은 상황·입력·기대 결과·금지 결과·검증 방법을 포함한다. 정상·부정·경계 관점을 검토하되 의미 없는 사례 수를 채우도록 강제하지 않는다.
- 데이터는 업무 의미·필수성·값의 범위·생성/수정/삭제 조건을 정의한다. NFR은 적용 범위와 관찰·측정 기준을 갖는다. DB 자료형·물리 인덱스 등 구현 선택은 설계에서 결정한다.
- 초안은 미완성으로 저장할 수 있다. 검토 준비/설계 진입에서 누락을 보고하고 AI가 임의 값을 넣어 통과시키지 않는다.

## 범위·관계

- 포함: REQ와 NFR에 각각 적합한 상세화. 필요 없는 UI·규제·보안 요구는 만들어내지 않는다.
- 관계: 002의 준비도, 004의 의미 검토, 005의 목록, 006의 사용자 검토.

## 인수 기준

- AC-003-1: 초안을 저장·재개할 수 있고 적용 필수 항목이 비면 검토 준비 판정에 정확한 보완 항목이 나온다.
- AC-003-2: UI 없는 배치 요구에 화면을 강제하지 않으며, 실제 수량 계산 요구의 경계 규칙은 낮은 변경 등급이어도 확인한다.
- AC-003-3: 미정 값을 해당 없음으로 위장하거나 측정 기준 없는 NFR을 완성된 것으로 인정하지 않는다.
- 검증 연결: ACC-003.
