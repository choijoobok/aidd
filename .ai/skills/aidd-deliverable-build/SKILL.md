# AIDD 제출 패키지

1. 대상 릴리스와 `DLP`, 포함·제외 규칙, 승인·게이트·잔여 위험과 독자를 확인한다.
2. 정본, 생성 문서, 실제 증거의 출처와 버전을 고정하고 `build/deliverables/<profile>/`에 패키지를 재생성한다.
3. 설계·사용자·운영 프로필을 분리하고 내부 결정·비밀정보·테스트 fixture가 고객 제출본에 섞이지 않게 한다.
4. 출시 프로필에서는 목업을 실제 화면으로 사용할 수 없으며, 미검증 자료와 승인되지 않은 필수 게이트가 있으면 패키지를 준비 완료로 표시하지 않는다.
5. 링크, 누락 자산, 브라우저·오프라인 열람, 인코딩과 패키지 manifest를 검사하고 빌드 명령·커밋·결과를 `EVD`에 연결한다.

`project/docs/generated/site/index.html`은 프로젝트 소개·개요·목적·주요 기능을 보여 주는 공통 홈이다. 좌측 상단 로고와 프로젝트명은 홈으로 돌아와야 하며, 이 페이지도 정본에서 재생성한다.

생성된 공통 홈은 설계·검증, 사용자, 운영·개발 문서 사이트로 연결한다. 각 사이트는 하나의 오프라인 HTML 파일에서 트리 목차, 제목·본문 검색, 인쇄, 테마와 글자 보기 설정을 제공한다. 고객용 문서의 내용은 정본과 생성 Markdown을 수정한 뒤 다시 만들며 HTML을 직접 고치지 않는다.

`build/deliverables/**`는 재생성 가능한 파생물이며 일반적으로 Git 정본에 포함하지 않는다.
