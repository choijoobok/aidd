# S08A — 선행 접속·인증·접근 정책 보완

사용자 승인 APR-007에 따른 S07A/S08 증분이다. S09 실행·실제 프로젝트 전환·커밋·릴리스 승인이 아니다.

## 실패와 목표

ACT 업무 권한과 SCR 적용 권한에 일반 문장만 있어도 접속·최초 화면·인증·인가가 빠진 채 ready가 되었다. 시스템 이해·역할 정의 직후 접근 정책을 확인하고 UC/요구/설계/시험까지 연결한다. 공개 시스템에도 로그인을 강제하지 않는다.

## 설계와 영향

- 기존 POL에 kind=system_access 계약을 정의한다. 접속 채널·진입점, 인증 방식/만료, 권한 기준/확인/강제/부여·회수, 규칙별 초기 화면·인증 후 목적지·기능/데이터 범위·거부 동작을 기록한다.
- ACT/UC.access는 정책 ID와 안정 rule key를 참조한다. 역할 간 공통 규칙은 재사용하고 모듈별 정책은 별도 ID 파일로 분리한다. 수작업·비접속 주체에는 구체적 비적용 사유를 허용한다.
- CHG.discovery.access_policies에 현재 범위 정책을 등록하고 intent 사용자 검토·기준선에 포함한다. 요구 확정 때 적용 규칙마다 derived_from(POL, selector) 연결을 확인한다.
- 공통 참조 추출을 통해 조회·인덱스·문서·영향·검토 해시에 연결한다. 정책 변경은 연결된 작업을 재검토 대상으로 만든다. 문장 의미와 정책 충돌의 최종 검토는 사용자와 AI 책임이다.
- portable 명세/CLI 내부 도구/스킬/프로젝트 가이드는 .ai에 둔다. 새 런타임 훅·스킬·플러그인은 추가하지 않는다. export의 기존 .ai 허용 목록으로 배포하며 관리 기록은 배포하지 않는다.

## 호환성과 롤백

KIT-CHG-018의 major 범위다. 판정기 버전을 변경하며 기존 ID·원문·RVW/BSL 이력은 보존한다. 새 필수 입력 없는 기존 정본은 초안으로 조회/저장 가능하지만 ready로 승격하지 않는다. 자동 정책 추정·사용자 승인 생성·제품 마이그레이션은 하지 않는다. 롤백은 이 증분 파일/개정만 선택적으로 되돌리고 새 정책 원문과 이후 사용자 변경을 별도로 보존한다. S02/S03 승인 파일은 수정하지 않는다.

## 검증 계획

공개/로그인 선행/혼합/백오피스/API·배치/비적용 정상 경로, 미정·누락·틀린 참조·역할 불일치·정책과 인증 모순·요구 연결 누락, 정책 변경의 stale/영향, 실제 저장·생성 문서 비교를 시험한다. 공유 판정기 변경에 따른 전체 회귀와 provider sync/check/hook self-test/smoke를 수행한다. 실제 제품 로그인 실행 및 외부 provider 행동은 검증 대상이 아니다.
