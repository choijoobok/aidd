# KIT-REQ-018-002 — 합의한 주기 전체 범위의 설계 진입

- 출처: 사용자 의도 — 모든 요구사항 검토 후 설계, 모듈별 독립 진행 / 계획 목표 3
- 목적: 검토되지 않은 요구를 남겨 두고 설계를 먼저 확정하는 일을 막는다.
- 대상·트리거: 특정 모듈·공동 변경의 요구분석을 마치고 설계에 진입할 때.

## 요구 동작

- 이번 주기에 포함·제외·보류한 요구사항과 적용 공통 조건을 사용자와 합의한 범위로 식별한다.
- 범위에 포함된 모든 요구사항의 적용 항목·의미 검토·사용자 검토·현재 유효성이 준비되어야 설계 진입을 허용한다.
- 영향을 주는 공통 규칙과 상대 모듈의 공개 계약을 확인한다. 무관한 모듈의 내부 요구분석 완료를 기다리게 하지 않는다.
- 미완료 요구를 자동 제외하거나 보류 표시만으로 설계 조건을 충족시키지 않는다. 범위 변경은 사용자 결정과 영향 검토를 남긴다.
- 이해를 돕는 스케치·가능성 실험은 탐색으로 식별할 수 있다. 탐색 산출물을 승인된 설계나 제품 구현 완료로 간주하지 않는다.

## 범위·관계

- 포함: 신규 모듈의 전체 최초 범위, 기존 모듈의 합의된 변경 범위, 공동 변경의 모듈별 경계.
- 제외: 영구히 추가될 모든 미래 요구사항의 사전 확정, 관련 없는 모듈 전체의 완료 대기.
- 관계: 003~007, 015, 021. 요구가 바뀌면 014로 되돌아간다.

## 인수 기준

- AC-002-1: 범위 내 3건 중 1건이 미검토면 그 ID와 사유를 표시하며 설계 진입을 거부한다.
- AC-002-2: 무관한 B의 초안이 존재해도 준비된 A의 설계 진입을 허용한다. A가 소비하는 미확정 B 계약이면 차단한다.
- AC-002-3: 미검토 요구를 목록에서 지운 변경은 범위 결정이 없으면 준비 완료로 인정하지 않는다. 승인된 범위 변경은 새 범위로 다시 판정한다.
- 검증 연결: ACC-002, E2E-001.
