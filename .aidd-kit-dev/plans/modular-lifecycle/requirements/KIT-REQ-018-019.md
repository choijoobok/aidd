# KIT-REQ-018-019 — 신규 프로젝트·추가 모듈·배포 경계

- 출처: 사용자 개발 완료 뒤 신규 모듈 추가 요청 / 계획 목표 1~2, 13~14
- 목적: Kit 원본뿐 아니라 배포된 새 프로젝트에서도 모듈별 흐름을 시작·확장한다.
- 대상·트리거: export, new-project, 운영 프로젝트의 추가 모듈 생성.

## 요구 동작

- 빈 Kit export와 제품 정본을 초기화하는 new-project를 구분한다. 새 구조의 인덱스·소유권·필수 진입점을 일관되게 준비한다.
- 초기 레코드는 실제 사용자 결정이 없는 내용을 승인 완료로 만들지 않는다. 샘플·기본값·fixture를 실제 요구나 검토 증거로 가장하지 않는다.
- 운영 프로젝트에 모듈을 추가할 때 기존 모듈의 정본·현재 승인·운영 기준선을 초기화하지 않는다. 새 모듈은 요구분석부터 진행하며 필요한 공통 계약만 연결한다.
- 폴더와 ZIP은 동일 staging·검증 경로 및 허용 목록을 따른다. 관리 계획·관리 스킬·fixture·대화 원문이 배포물에 섞이지 않는다.
- 출처 정보와 버전 영향은 기록하되 자동 업그레이드 보증으로 해석하지 않는다. 실제 릴리스 준비는 별도 명시적 실행으로 구분한다.

## 범위·관계

- 포함: 생성된 임시 프로젝트에서 실제 대표 흐름 검증, 기존 출력 덮어쓰기 방지.
- 제외: 루트 kit-source에 제품 project 생성, 승인 상태를 저장하는 새로운 startup 인증 절차.
- 관계: 001~003, 008~010, 018, 020~021.

## 인수 기준

- AC-019-1: 새 프로젝트에서 요구 초안→검토→설계→작업 개발 흐름을 시작할 수 있으며 가짜 승인이 없다.
- AC-019-2: A 운영 중 B를 추가해도 A의 정본·기준선이 보존되고 B는 자체 요구분석을 시작한다.
- AC-019-3: 폴더/ZIP의 공개 payload가 일치하고 관리·대화 자료는 제외되며 기존 출력 대상은 덮어쓰지 않는다.
- 검증 연결: ACC-019.
