# KIT-REQ-018-007 — 정의·구현·유효성 분리와 개정본 식별

- 출처: 사용자 의도 — 상태 관리와 언제든 이전 단계 복귀 / 계획 목표 8~9
- 목적: 과거 승인·완료와 현재 변경에 대한 준비도를 혼동하지 않는다.
- 대상·트리거: 요구·설계·기준선 수정, 준비도 검사, 과거 결과 재사용.

## 요구 동작

- 작성/검토 단계, 구현/운영 결과, 현재 내용에 대한 검토 유효성을 구분한다. 사용자 검토 완료가 구현 완료를 뜻하지 않는다.
- 검토·게이트·테스트가 대상으로 삼은 내용과 관련 입력 기준선을 식별한다. 결정에 영향을 주는 내용이나 의존 기준선이 바뀌면 현재 유효성을 다시 판단한다.
- 해시는 차이 감지 수단이며 의미적 동등성 판정으로 사용하지 않는다. 제목·근거·출처도 의미 영향이 있을 수 있으므로 일괄 면제하지 않는다.
- 순수 표현·파일 이동 등 동등성 확인은 범위와 이유를 남겨 검토를 재사용할 수 있다. 실제 정책·인수 기준 변화는 재검토한다.
- 읽기·검사 명령은 낡은 결과를 표시하고 진입을 막을 수 있지만 승인 이력이나 정본 상태를 조용히 덮어쓰지 않는다.

## 범위·관계

- 포함: 자기 내용과 의존 기준선 변화, 승인 뒤 변경, 역사적 결과 보존.
- 제외: 모든 수정마다 전체 프로젝트를 초안으로 되돌리기, 실행된 테스트 결과의 과거 사실 삭제.
- 관계: 006, 010, 012, 014~017, 020.

## 인수 기준

- AC-007-1: 승인된 요구의 인수 기준 변경 후 과거 승인은 조회되지만 현재 검토 유효성은 낮아지고 관련 진입이 차단된다.
- AC-007-2: 검사를 반복해도 원본·승인 이력이 바뀌지 않으며 동일 입력의 판정이 같다.
- AC-007-3: 내용이 같은 파일 이동은 ID와 검토 연결을 보존한다. 오탈자라는 주장만으로 업무 의미 변화의 재검토를 생략하지 않는다.
- 검증 연결: ACC-007.
