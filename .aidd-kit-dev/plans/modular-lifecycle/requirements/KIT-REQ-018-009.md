# KIT-REQ-018-009 — 계층 인덱스와 범위별 조회

- 출처: 사용자 의도 — 파일을 쉽게 찾아 효율적으로 읽고 분석 / 계획 목표 10~12
- 목적: 정본을 나눈 효과가 실제 탐색과 AI 입력 범위 축소로 이어지게 한다.
- 대상·트리거: 모듈·ID·주기 조회, 파일 추가·변경 후 인덱스 갱신.

## 요구 동작

- 프로젝트→공통/모듈→유형/항목을 탐색할 수 있는 계층 인덱스를 정본에서 재생성한다. 인덱스에 업무 내용을 독립적으로 다시 작성하지 않는다.
- ID·유형·제목·소유·경로·개정/유효성에 필요한 정보·참조 관계로 해당 레코드와 관련 의존을 찾는다. 인덱스도 규모에 따라 분할할 수 있다.
- 단일 모듈의 상세 조회는 대상과 필요한 공통·의존 레코드 본문을 읽고 무관한 모듈 본문을 전부 파싱하지 않는다. 파일 목록·변경 여부 메타데이터 확인은 허용한다.
- 새 파일·누락·이동·낡은 인덱스를 검출해 복구 또는 명확한 갱신 필요를 표시한다. 인덱스 누락을 요구사항 없음이나 준비 완료로 해석하지 않는다.
- 조회 범위의 유효성과 프로젝트 전체 검증 여부를 구분한다. 부분 조회 성공을 전체 정상이라고 보고하지 않는다.

## 범위·관계

- 포함: 인덱스 재생성, 무관한 데이터 오류의 격리된 진단, 전역 참조 검증 경로.
- 제외: 근거 없는 성능 초수 보장. 효율은 대표 규모에서 읽은 레코드 범위와 작업량으로 먼저 검증한다.
- 관계: 008, 010, 014~017.

## 인수 기준

- AC-009-1: 여러 모듈 fixture에서 A 조회의 본문 읽기 대상을 계측하면 A와 실제 의존에 한정된다.
- AC-009-2: 인덱스에서 누락된 새 요구는 갱신/검사로 발견되며 해당 범위의 게이트를 잘못 통과시키지 않는다.
- AC-009-3: 무관한 B 본문 오류가 A 상세 조회를 무조건 중단시키지 않는다. 전체 검증에서는 B 오류가 보고되고, B에 의존하는 판정은 미확인 상태를 숨기지 않는다.
- 검증 연결: ACC-009.
