# KIT-REQ-018-010 — 동시 수정·부분 실패·변경 복구

- 출처: 합의한 파일·인덱스 구조의 일관성 보완 / 계획 목표 8~11
- 목적: 여러 세션과 다중 파일 갱신에서 데이터 유실이나 잘못된 승인 적용을 막는다.
- 대상·트리거: 정본 저장·이동·분할·승인 반영·인덱스 갱신·전환 중 실패.

## 요구 동작

- 수정 시 읽었던 개정본과 현재 값의 충돌을 검출한다. 같은 대상의 동시 변경에서 뒤의 작업이 앞의 변경을 조용히 덮어쓰지 않는다.
- 연결된 여러 파일의 변경이 실패하면 원복하거나 재개 가능한 불완전 상태와 범위를 명시한다. 중간 상태로 게이트를 통과시키지 않는다.
- 서로 다른 모듈의 독립 변경은 내용 충돌 없이 보존한다. 내부 쓰기 직렬화 자체는 허용하며 특정 동시 처리 성능을 강제하지 않는다.
- 정본 저장 성공·인덱스 갱신 실패를 구분하고 재생성으로 복구한다. 같은 작업 재시도로 중복 승인·ID·이력이 생기지 않게 한다.
- 복구·되돌림은 해당 작업의 변경 범위를 식별하고 이후 사용자 변경과 과거 승인·증거를 보존한다.

## 범위·관계

- 포함: 로컬 파일·프로세스 환경의 충돌/실패 처리와 재현 가능한 fault injection.
- 제외: 분산 DB·서버를 새로 도입하거나 모든 편집기의 원자성을 보장하는 것.
- 관계: 007~009, 014, 020.

## 인수 기준

- AC-010-1: 같은 개정본에서 시작한 두 수정 중 나중 저장은 충돌을 알리고 기존 결과를 덮어쓰지 않는다.
- AC-010-2: 다중 파일 작업 도중 실패를 주입하면 원복/재개 범위가 식별되고 불완전한 결과가 준비 완료로 나오지 않는다.
- AC-010-3: 독립 모듈 변경과 실패 후 재시도에서 레코드 유실·중복 이력이 없고 정본에서 인덱스를 복구할 수 있다.
- 검증 연결: ACC-010.
