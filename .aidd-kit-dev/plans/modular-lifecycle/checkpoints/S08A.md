# S08A — 접속·초기 화면·인증·인가 보완 완료

APR-007의 보완 구현과 자동 검증을 완료했다. S09 이후·실제 제품 전환·커밋·릴리스는 실행하지 않았다. [추가 명세](../supplements/S08A-system-access.md)와 [portable 계약](../../../../.ai/spec/system-access.md)을 따른다.

## 결과

- 기존 POL(kind=system_access)에 접속 채널·진입점, 인증 필요 여부/방식/만료, 권한 기준/확인/강제/부여·변경·회수, 규칙별 초기 화면·인증 후 목적지·기능/데이터 범위·미인증/권한 부족 결과를 정의했다.
- ACT/UC.access는 정책 ID와 rule key를 참조한다. 공통 정책 재사용과 모듈별 분리, 공개형·인증 선행·혼합형, API/배치, 비접속 역할/수작업 사유를 지원한다.
- CHG.discovery.access_policies, intent 사용자 검토와 BSL, 사용 규칙별 derived_from 요구 출처를 판정한다. 이미 정해진 공통 정책의 다른 모듈용 규칙까지 현재 모듈 요구로 강제하지 않는다.
- 누락/미정/잘못된 참조/인증 모드 모순/역할 불일치/시스템 처리의 비접속 선언/요구 연결 누락은 준비도를 차단한다. 초안 저장은 유지한다.
- 기존 참조 파이프라인으로 조회·인덱스·검토 digest·영향·브리핑·ID별 문서·내부 설계 제출에 연결했다. 정책 변경은 연결된 검토/작업의 재검토를 요구하고 역사적 승인·기준선은 수정하지 않는다.
- discovery/architecture/lifecycle 스킬, 참조/가이드, manifest와 템플릿 필드 계약을 보완하고 두 provider 생성 복사본을 동기화했다. 새 런타임 훅·스킬·플러그인은 없으며 export 허용 목록 경계를 유지했다.

## 한계와 재개

비어 있지 않은 문장의 업무적 충분성·정책 간 의미 모순은 사용자/AI 검토 대상이다. 자동 검사는 실제 제품 인증·인가 구현이나 공격 방어를 검증한 것이 아니다. 실제 외부 provider 수행·브라우저 시각 검토는 not_run이다.

판정기 2.3으로 기존 검토를 자동 승격하지 않는다. 기존 ID·현재 원문·RVW/BSL/REL 이력은 보존한다. major/in_progress, 버전 1.0.0 유지. 롤백은 이 증분의 코드/계약/생성 provider 변경만 선택적으로 되돌리고 새 정책 및 후속 사용자 변경을 보존한다.

다음 S09는 승인 대기다. 후보 변환 설계에서 이번 신규 접속 항목도 미확정 상태로 보존하고 자동 로그인 정책/승인을 만들지 않아야 한다. 계정 전환 시 status.json → 이 체크포인트 → 구현 맵을 읽고 이어간다.
