배포·운영 맥락과 설계 위험 예방

DPP-001 — 배포·운영 맥락 우선 정책

  • 상태: `최신`
  • 요구사항: REQ-016, REQ-018, REQ-020, REQ-021

세부 값을 미룰 수는 있지만 설계를 바꾸는 환경 범주는 미룰 수 없다. 미정 항목은 가정으로 숨기지 않고 담당자·결정 기한·영향과 함께 미결사항으로 기록한다.

필수 순서

  1. 제품 의도·성과·범위 확인
  2. DG-001 배포·운영 맥락 확인 게이트
  3. 품질 속성·워크로드·동시성 불변 조건 정의
  4. TG-001 기술 스택 선정 게이트
  5. 아키텍처·데이터·트랜잭션·실행 토폴로지 설계
  6. TG-002 개발 기반 준비도와 위험 시나리오 검증
  7. 기능 증분 개발

조기에 확인할 환경 범주

  • 온프레미스·클라우드·하이브리드와 사용 가능한 실행 플랫폼
  • 단일·다중 인스턴스와 자동 스케일 인·아웃 필요 여부
  • 조직이 지정한 DBMS·버전·운영 방식과 변경 가능성
  • 평균·최대 부하, 데이터 크기·증가율과 배치 시간창
  • 응답시간·처리량·가용성 SLO와 RTO·RPO
  • 강한 일관성이 필요한 업무 불변 조건과 최종 일관성 허용 범위
  • 세션·캐시·스케줄 작업·파일 등 인스턴스 로컬 상태 허용 여부
  • 보안·개인정보·규제·네트워크·운영 조직과 예산 제약

상세 설계까지 미룰 수 있는 값

  • 최종 인스턴스 수와 세부 사양
  • 자동 확장 임계값
  • 클라우드 서비스 세부 등급과 구매 옵션
  • 커넥션·스레드 풀의 최종 수치
  • DBMS 마이너 버전과 캐시 TTL

DEP-001 — AIDD 기반 구조 배포 프로필

  • 범위: 이 저장소의 방법론 프레임워크와 CLI
  • 상태: `승인됨`
  • 요구사항: REQ-001, REQ-013, REQ-020
항목기준
환경개발자 로컬 또는 CI 실행 환경의 저장소 기반 CLI
호스팅온프레미스·클라우드에 종속되지 않음
런타임Python 3.11 이상 단기 실행 프로세스
토폴로지호출 단위 단일 프로세스이며 장기 실행 서비스 인스턴스가 없음
확장서비스 자동 확장 적용 대상 아님. 병렬 CI 작업은 격리된 체크아웃을 사용해야 함
DBMS실행 DBMS 없음. UTF-8 무 BOM JSON과 Git이 정본 저장소 역할을 함
상태공유 쓰기 저장소에서 동시 생성·동기화 명령을 실행하지 않는 것을 현재 운영 가정으로 함
워크로드프로젝트 크기의 JSON·Markdown 파일을 결정적으로 생성·검증하는 배치형 작업
가용성·복구Git 이력과 저장소 복구 가능성이 기준이며 온라인 서비스 SLO·RTO·RPO는 적용 대상 아님
보안·운영저장소 권한, 훅 신뢰 검토, CI 비밀정보 분리와 변경 검토를 사용함

남은 가정

  • 실제 제품 파일럿에서는 별도 DEP 프로필을 만들고 DG-001을 다시 통과해야 함

RUN-001 — 정본 생성·검증 복구

  • 상태: `최신`
  • 범위: AIDD 정본과 생성 문서
  • 모듈: MOD-DOC, MOD-QA, MOD-DELIVERY
  • 요구사항: REQ-025, REQ-033
  • 트리거: 생성 문서가 오래됨; 정본 참조 검증 실패; 생성 중단

절차

  1. python .ai/tools/aidd.py generate를 실행한다.
  2. python .ai/tools/aidd.py validate를 실행한다.
  3. 검증 실패의 정본 ID와 원인을 수정하고 다시 생성한다.
  4. 전체 unittest를 실행하고 결과를 EVD에 연결한다.

검증

  • 생성 명령과 검증 명령이 모두 종료 코드 0이다.

롤백

정본과 생성기 변경을 함께 되돌린 뒤 다시 생성·검증한다.

에스컬레이션

반복 실패 또는 데이터 손실 위험은 프로젝트 책임자와 거버넌스 담당에게 알린다.

정상 운영 점검

정본 변경 후 생성, 동기화, 검증, 테스트 순서로 실행한다. 생성 문서를 직접 수정하지 않는다.

```powershell python .ai/tools/aidd.py generate python .ai/tools/aidd.py sync-ai python .ai/tools/aidd.py validate python -m unittest discover -s .ai/tests -v ```

릴리스와 개발 시작 점검

개발 시작과 릴리스는 서로 다른 게이트다. 차단 메시지를 해소하거나 승인된 예외를 기록하기 전에는 상태를 올리지 않는다.

```powershell python .ai/tools/aidd.py development-check --change CHG-001 python .ai/tools/aidd.py release-check --release REL-001 ```

병합 영향 대응

병합 후 생성된 MRG 레코드의 영향 모듈, 충돌 해결 근거와 추가 테스트 결정을 기록한다. 필요한 재검토·재테스트는 담당자 없이 MRC로 남기고, PM·관리자의 오프라인 지시 뒤 실제 수행자·시각·결과·증거만 완료 기록에 남긴다.

  1. post-merge 훅이 만든 MRG ID를 확인한다.
  2. 양쪽 부모와 결과를 비교한다.
  3. assess-merge로 모듈·메모·추가 테스트 결정을 기록한다.
  4. add-merge-recheck으로 릴리스 차단 여부와 대상 모듈·TC를 기록하되 담당자는 배정하지 않는다.
  5. 필요한 재검토·회귀 테스트를 실행하고 EVD를 연결한 뒤 complete-merge-recheck으로 실제 수행 결과를 남긴다.

장애 복구

검증 실패 시 오류가 가리키는 정본을 수정하고 재생성한다. 정본 JSON이 손상되면 Git의 마지막 정상 커밋과 변경 기록을 비교해 복구하며 생성 문서에서 역으로 덮어쓰지 않는다.

  1. 현재 변경과 오류를 보존한다.
  2. UTF-8 BOM·JSON 구문·끊어진 ID·오래된 생성 문서 순으로 확인한다.
  3. 가장 작은 정본 수정을 적용한다.
  4. 전체 검증과 관련 회귀 테스트를 다시 실행한다.

보호 자산과 신뢰 경계

보호 자산은 고객 의도와 승인 기록, 정본 JSON, 소스·테스트, CI 설정, 비밀정보와 출시 증거다. 사용자 입력, 저장소 콘텐츠, AI 출력, 로컬 훅, CI 실행기와 외부 연동 사이를 신뢰 경계로 취급한다.

주요 위협

프롬프트 주입으로 정본 규칙을 우회하는 행위, 승인·증거 위조, 악성 훅 또는 CI 변경, 비밀정보 커밋, 생성 문서 드리프트, 권한 없는 원격 설정 변경과 공급망 변조를 검토한다.

필수 통제

최소 권한, 보호 브랜치와 승인, 불변 커밋 기반 증거, 비밀정보 외부 보관, 의존성 고정·검토, 입력을 지시가 아닌 데이터로 취급하는 규칙, 로그의 민감정보 제거와 롤백을 적용한다.

검증 절차

정본 참조 부정 테스트, 게이트 우회 테스트, AI 행동 평가, CI 필수 검사, 병합 영향 검토와 배포 프로필에 맞는 위협·장애 테스트를 수행한다. 발견사항에는 영향 ID, 증거, 결과와 개선안을 기록한다.
