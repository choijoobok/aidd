# 유즈 케이스 목록

## UC-001 — 변경 범위화와 통제

- 주 행위자: 고객
- 보조 행위자: AI 제품 분석가, AI 아키텍트, AI 품질 검토자
- 시작 조건: 고객이 AI에 시스템 기능 생성 또는 변경을 요청한다.
- 요구사항: REQ-004, REQ-005, REQ-006, REQ-007, REQ-017

### 기본 흐름

1. AI가 결정 대상, 기대 성과, 영향 사용자, 제약과 미지수를 식별한다.
2. 고객이 의도를 명확히 하고 중요한 트레이드오프를 선택한다.
3. AI가 안정적인 ID를 부여하고 요구사항, 모듈, 위험, 미결사항과 변경 등급을 기록한다.
4. AI가 위험에 비례하는 아키텍처와 검증 증거를 제안한다.
5. 고객이 중요한 결정과 범위를 승인한다.
6. AI가 최신 파생 산출물을 생성하고 추적성을 검증한다.

### 대안 및 예외 흐름

- C0 변경은 집중 검증을 포함한 단축 경로를 사용한다.
- 중대한 모호성이 남으면 구현 전에 멈추고 미결사항을 보존한다.

### 사후 조건

- 변경에 감사 가능한 의도, 범위, 결정, 롤백과 검증 경로가 있다.

## UC-002 — 증분 검증과 출시

- 주 행위자: 고객
- 보조 행위자: AI 개발자, AI 테스터, AI 보안 검토자, AI 운영자
- 시작 조건: 개발 증분이 완료 후보로 제시된다.
- 요구사항: REQ-003, REQ-015, REQ-016, REQ-018

### 기본 흐름

1. AI가 코드, 테스트, 텔레메트리, 마이그레이션, 롤백과 관련 가이드를 갱신한다.
2. AI가 결정적 검증과 위험 기반 테스트를 수행한다.
3. AI 품질 보증 관점이 추적성, 보안, 테스트 증거와 잔여 위험을 검토한다.
4. AI가 정본 레코드에서 릴리스 차단사항을 계산한다.
5. 고객이 출시 여부와 잔여 위험을 결정한다.
6. 운영 성과와 장애를 새로운 추적 변경으로 환류한다.

### 대안 및 예외 흐름

- 게이트 실패 시 해당 생애주기 상태로 되돌아간다.
- 승인된 예외에는 담당자, 만료와 보완 통제를 기록한다.

### 사후 조건

- 릴리스 결정에 증거가 있고 되돌릴 수 있다.
