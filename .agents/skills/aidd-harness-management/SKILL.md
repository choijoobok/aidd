# AIDD 하네스 관리

모듈별 정본 조회·전문 명령·게이트는 [v2 통합 계약](../../../.ai/spec/specialty-integration.md)을 적용한다. 현재 owner/CHG 범위를 먼저 고르고 공통 정의를 참조한다. 쓰기 명령에는 고유 operation을 사용하며 사용자 결정·현재 유효성·실제 실행을 구분한다.

1. **훅 격리를 다른 모든 기준보다 먼저 지킨다.** provider·이벤트·책임별로 전용 `.mjs` 실행 파일과 전용 프로세스를 사용하며, 런타임 훅끼리 공통 dispatcher·공통 라이브러리·상호 import·상호 호출을 금지한다. 코드 중복은 허용한다. 한 훅의 추가·수정·삭제가 다른 훅의 명령, 실행 파일, 등록 인덱스 또는 승인 해시를 바꾸면 안 된다. provider의 단일 등록부 제약 때문에 이를 보장할 수 없으면 구현을 중단하고 그 한계를 사용자에게 알린다.
2. 공통 AI 수행 계약은 루트 `AGENTS.md`를 단일 정본으로 사용하고 `CLAUDE.md`는 이를 import하는 얇은 Claude 전용 어댑터로 유지한다. 공통 스킬·훅·도구·템플릿은 `.ai`를 정본으로 사용하며 provider별 JSON·스킬 복사본을 직접 고치지 않는다.
3. 새 훅·스킬·도구·플러그인은 해결할 실패, 기존 수단 부족, 트리거·입출력 계약, 중복 여부, 비활성화·롤백을 먼저 검토한다. 보안·권한 검사는 적용 정본이나 사용자가 명시적으로 요구할 때만 추가한다.
4. 공통 행동 계약은 `.ai/hooks/contract.json`에 정의하되 런타임 코드는 공유하지 않는다. Codex와 Claude의 지원 이벤트·입력 차이는 각자의 독립 실행 파일에서 처리하며 한 provider에 없는 이벤트를 지원되는 것처럼 가장하지 않는다.
5. 보호 훅의 정책 거부와 런타임 고장을 구분한다. 정상 정책 거부를 우회하지 않으며 다른 훅을 복구 차선으로 호출하지 않는다.
6. 프로젝트에서는 변경 후 `node .ai/tools/aidd.mjs sync-ai`, `node .ai/tools/aidd_hook.mjs self-test --hook`, 관련 행위 테스트를 실행한다. Kit 원본의 provider 동기화와 릴리스 검증은 배포되지 않는 관리자 가이드를 따른다. provider별 별도 평가나 기록은 사용자가 요청하거나 실제 provider 차이를 재현할 때만 만든다.
