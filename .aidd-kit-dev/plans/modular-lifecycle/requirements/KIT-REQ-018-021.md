# KIT-REQ-018-021 — 공통 기준선·계약 재사용과 통합 검증

- 출처: 모듈 독립성·전체 일관성의 동시 충족 / 계획 목표 1~2, 7~9, 11, 14
- 목적: 모듈이 독립적으로 진행하면서 공통 설계와 실제 연동 결과를 일관되게 유지한다.
- 대상·트리거: 공통 아키텍처·데이터·UI·개발/운영 기준 채택, 모듈 간 계약 변경과 통합.

## 요구 동작

- 프로젝트 공통 기준과 계약은 소유 정본·적용 범위·개정본·소비 대상을 식별한다. 이미 검토된 유효한 기준을 새 모듈이 재사용할 수 있으며 모든 내용을 매번 새로 승인받게 하지 않는다.
- 새 모듈/변경이 공통 기준에 맞는지 확인하고 불일치·누락·계약 변경이 있으면 해당 영향에 한해 재검토한다. 외부 시스템의 계약 변화도 관련 의존으로 다룬다.
- 모듈 간 계약만 합의되어도 진행 가능한 작업과 상대 실제 구현·환경이 필요한 작업을 구분한다. 합의된 계약의 stub/mock 검증과 실제 통합 검증을 구분한다.
- 실제 통합이 필요한 릴리스는 해당 조합·개정본·환경의 실행 증거를 갖춰야 한다. 상대 모듈 미구현·환경 미준비를 계약 승인만으로 출시 완료 처리하지 않는다.
- 공통 기준 변경은 소비 범위에 영향을 분석하되 기존 배포를 자동 철회하지 않는다. 별도 운영 조치가 필요하면 근거와 결정 요청으로 연결한다.

## 범위·관계

- 포함: 기존 아키텍처·플랫폼 기준선과 변경별 적합성·통합 계약의 재사용.
- 제외: 모든 모듈을 강제로 독립 배포하거나 동일 시점 릴리스하도록 정하는 것, 특정 인프라를 새로 강제하는 것.
- 관계: 001~002, 005~007, 011~016, 019.

## 인수 기준

- AC-021-1: 유효한 공통 기준을 채택한 새 모듈은 중복 정본·불필요한 전체 재승인 없이 진행하고 적용 근거를 조회할 수 있다.
- AC-021-2: 합의된 연동 계약으로 개발·stub 검증을 진행해도 실제 통합 증거가 필요한 릴리스는 그 증거 없이는 통과하지 않는다.
- AC-021-3: 공통/외부 계약 변경 시 관련 소비 작업을 재판정하고 무관한 모듈 및 과거 운영 기준선은 보존한다.
- 검증 연결: ACC-021.
