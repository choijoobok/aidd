# 완료와 릴리스 게이트

변경 완료란 결정된 동작이 구현되고, 연결된 테스트가 통과하며, 필수 검토가 해결되고, 문서와 운영 자산이 최신이며, 텔레메트리가 충분하고, 롤백이 신뢰할 수 있음을 뜻한다. 다중 인스턴스·비동기·외부 연동·고부하가 적용되면 로컬 단위 테스트만으로 완료할 수 없고 경쟁·중복·스레드 전환·부하·장애·복구 증거를 남긴다. 모든 예외에는 위험, 결정 주체·이유, 만료와 보완 통제가 있어야 한다.

릴리스 준비 완료에는 호환 가능한 산출물, 마이그레이션·복구 증거, 미해결 차단사항 없음, 치명적 잔여 위험 수용, 지원 담당과 고객의 출시 결정이 추가로 필요하다. 배포 성공은 성과 달성이 아니므로 출시 후 지표와 피드백 기간을 정의한다.

자유문자 결과나 파일 존재만으로 통과를 선언하지 않는다. 통과 테스트에는 구조화된 증거가, C2·C3 완료에는 변경별 필수 게이트의 `passed` 결과가 있어야 한다. 통과 게이트는 불변 커밋을 가리키며 이후 영향 변경이 있으면 다시 평가한다.

기능 구현 시작은 출시 준비와 별개로 `development-check`를 통과해야 한다. 완료 `WRK`에는 인수 기준을 충족한 `EVD`가 있어야 하며, 운영·사용자·보안 가이드에 영향을 주는 변경은 같은 증분에서 정본과 생성 문서를 갱신한다.

변경 위험과 프로젝트가 정한 방식에 맞는 검토도 완료 조건이다. 필요한 독립 검토가 있다면 구현과 분리된 AI 세션, 교차 provider 평가 또는 별도 사람 검토의 실제 증거를 남긴다. AIDD는 팀원 명부나 승인 권한을 판정하지 않는다.
