AIDD 사용자 매뉴얼

  • 대상: 제품 책임자와 프로젝트 참여자
  • 상태: `최신`
  • 적용 범위: 요청 등록, 결정, 상태 확인, 출시 승인
  • 관련 요구사항: REQ-004, REQ-005, REQ-007, REQ-008, REQ-015, REQ-025

새 프로젝트 또는 변경 시작

원하는 기능보다 해결할 문제, 대상 사용자, 기대 성과와 하지 않을 범위를 먼저 설명한다.

  1. 문제와 기대 성과를 제시한다.
  2. AI가 제시한 가정과 미결사항을 확인한다.
  3. 중요한 트레이드오프의 장단점과 가역성을 비교한다.
  4. 선택 결과가 ADR·REQ·CHG ID로 기록되었는지 확인한다.

설계와 개발 승인

배포 환경과 품질 제약을 먼저 정하고 기술 스택과 개발 기반을 순서대로 승인한다. 모르는 값은 추측하지 않고 담당자·기한·영향이 있는 미결사항으로 남긴다.

진척 확인

세션 시작에는 경영진 뷰로 짧게 브리핑하고, 평가 대기 병합과 대기 MRC를 일반 진척과 분리해 먼저 확인한다. MRC는 사전 담당자 없이 PM·관리자가 오프라인으로 조율하며 완료 뒤 실제 수행 결과를 기록한다.

```powershell node .ai/tools/aidd.mjs status --level executive node .ai/tools/aidd.mjs status --level detail node .ai/tools/aidd.mjs status --level module --module MOD-AI ```

결정 취소와 변경

기존 결정을 삭제하지 않는다. 새 ADR이 이전 ADR을 대체하도록 연결하고 영향받는 요구사항·작업·테스트·롤백을 갱신한다.
