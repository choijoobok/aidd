# 프로젝트 개발 기반 설계

개발 기반은 기술 스택 선정 뒤 프로젝트별로 만든다. AIDD 공통 방법론에 특정 프레임워크·라이브러리 규칙을 박지 않는다.

- `STD`: 개발·보안·테스트·관측성·배포 표준. 자동 실패가 드러나는 `contract`와 별도 검사가 필요한 `policy`를 구분한다.
- `UXB`: 디자인 토큰, 앱 셸, 내비게이션, 접근성과 반응형 기준선.
- `UIP`: 레이아웃과 상호작용, 로딩·빈 상태·오류·권한 상태 패턴.
- `CMP`: 안정 ID를 가진 공통 컴포넌트 계약, 구현 위치, 사용 모듈과 테스트.
- `GPH`: 표준을 실제로 적용한 골든 패스와 재현 가능한 검증.
- `EXC`: 표준 예외의 사유, 위험, 보완 통제, 책임자, 만료와 재검토 조건.

AI는 UI 대안 2~3개의 가치·비용·위험·가역성을 제시하고 고객 승인 뒤 기준선을 확정한다. 두 화면 이상에서 반복되거나 접근성·보안·오류 처리처럼 일관성이 중요한 요소, 여러 모듈에 영향을 주는 계약만 공통 컴포넌트 후보로 올린다. 문서만으로 기반 완료를 선언하지 않고 참조 구현과 계약·접근성·부정·회귀 증거를 연결한다.

모듈은 공통 기반을 복사하지 않고 안정 ID로 참조한다. 모듈별 차이는 `EXC` 또는 모듈 전용 정본에 두며, 공통 계약 변경은 사용 모듈·화면·테스트의 재검증 대상을 산출한다.
