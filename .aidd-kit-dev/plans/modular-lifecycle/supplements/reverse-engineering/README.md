# S08B — 일반 레거시 역분석과 AIDD 정본 도입

상태: 요구·단계안 작성 완료, 세부 설계/구현 착수 승인 대기. 아래는 제안이며 구현된 기능 목록이 아니다. 이전 AIDD 버전 전용 변환을 취소한 KIT-ADR-011은 유지한다.

## 목표와 경계

AIDD와 무관한 기존 시스템의 소스·문서·산출물에서 근거 있는 초안을 자동 작성하고, 시스템 개요부터 사용자와 순차 검토·보완하여 모듈별로 AIDD 정본을 채택한다. 현재 구현과 원하는 요구를 구분하고 운영 중인 시스템을 중단하거나 다시 만들지 않는다.

이 작업에서 마이그레이션은 개발·문서 관리 체계를 AIDD로 도입하는 뜻이다. 실제 업무 데이터 이관, DB 변경, 제품 리팩터링, 운영 배포, 기존 소스 이동 및 이전 AIDD 버전 변환은 별도 요청 없이는 수행하지 않는다.

## 실행 단계 제안

| 단계 | 구현 범위 | 완료 확인 |
|---|---|---|
| S08B-1 | 구체 데이터/명령 계약 설계, 범용 자료 인벤토리·출처/관측·정본 초안 생성 핵심 | 원본 불변, 읽지 못한 자료 표시, 근거/추론 분리, ID/참조·재실행·미승인 상태 |
| S08B-2 | 사용자 검토 묶음·차이/질문·요구 포괄성, 재분석 병합·영향·스킬/브리핑/문서 통합 | 부분 승인·stale·충돌·선택적 재개, 사용자 수정 보존 |
| S08B-3 | 모듈별 도입 준비도, 기존 구현 연결·대표 동작 검증, end-to-end fixture/가이드 | 문서 도입/실제 동작 검증/운영 상태의 분리, 신규 변경의 정상 AIDD 주기 연결 |

각 단계 완료 후 상태와 검증을 기록하고 다음 단계 승인을 받는다. S08B 완료 후 축소된 S09(신규 프로젝트·export·v2 배포 기준 정리)와 S10 최종 인수를 이어간다. 아직 특정 제품의 언어·프레임워크·문서 포맷을 지정받지 않았으므로 모든 스택의 전용 파서를 약속하지 않는다. 첫 단계는 Node 표준 라이브러리 범용 수집/출처/초안 계약과 AI 분석의 연결에 집중한다. 전용 추출기는 실제 대상과 효용을 확인한 뒤 별도 범위로 추가한다.

## 영향과 검증

기존 LDP/SURF/CHG/WRK, SYS/CAP/ACT/POL/UC/BPR/REQ/NFR/FEAT/SCR/DAT/NAV/IFC, RVW/BSL/IMP를 우선 재사용한다. 관측 출처와 초안 매핑에 필요한 필드·저장 위치·CLI는 S08B-1에서 명세와 함께 확정한다. 검증되지 않은 extensions를 넣어 ready를 우회하지 않는다.

portable 계약·도구·스킬·가이드는 .ai, Kit 실행 기록과 회귀 자료는 .aidd-kit-dev에 둔다. 신규 runtime 훅·별도 서비스·DB는 기본 해법이 아니다. 기존 저장/CAS·인덱스·검토·영향 계산과 두 provider를 사용한다. 기존 .ai export 경계를 유지하고 실제 스킬/생성기 변경 단계에서 sync/check/smoke를 수행한다.

KIT-CHG-018의 major 개편에 증분으로 포함하되 구현 전이다. S02/S03 승인본과 완료된 S08A를 재작성하지 않는다. 롤백은 이 기능이 만든 초안/개정만 작업별로 식별하고 이후 사용자 수정과 검토 이력을 보존한다. 승인된 정본이나 원본 코드를 일괄 삭제하는 초기화는 제공하지 않는다.
