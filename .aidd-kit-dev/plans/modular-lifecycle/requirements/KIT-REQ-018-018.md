# KIT-REQ-018-018 — 전체 스킬·훅·도구 계약의 일관성

- 출처: 사용자 모든 스킬·훅 재검토 요청 / 계획 목표 12~14
- 목적: 새 구조를 도입해도 수행 지침이나 자동 처리가 구형 경로·판정으로 돌아가지 않게 한다.
- 대상·트리거: 구조 변경의 영향 조사, 단계별 관련 구현, 통합 점검.

## 요구 동작

- 모든 portable/관리 스킬과 references, 훅, provider 어댑터, CLI, 템플릿, 가이드, 생성기, manifest를 목록화하고 유지·수정·교체 및 이유를 기록한다. SKILL.md만 검토하고 연결 문서를 누락하지 않는다.
- 스킬은 사람·AI의 수행 순서·의미 검토·질문을 안내하고 일반 도구는 구조·조회·준비도 판정을 제공한다. 같은 상태 로직을 각 스킬이 따로 정의하지 않는다.
- 훅은 provider·이벤트·책임별 독립 프로세스를 유지한다. 런타임 공통 dispatcher·라이브러리·상호 import/호출을 도입하지 않는다. 한 훅 변경이 다른 훅 명령·등록·승인 해시를 바꾸지 않게 한다.
- 정본 변경에 필요한 보호·후처리 훅만 새 경로에 맞춘다. 대화 로그는 정본·증거·배포물과 분리하고 기존 provider 역할·독자 경계를 유지한다.
- 스킬 원본에서 provider 어댑터를 동기화하고 실제 수행 시나리오를 점검한다. 파일 일치 검사와 실제 provider 행동 검증을 구분하며 미실행 항목은 명시한다.

## 범위·관계

- 포함: Node.js 22 이상·표준 라이브러리, UTF-8 BOM 없음·LF, 독립 훅 계약 유지.
- 제외: 근거 없이 새 훅·플러그인을 추가하거나 보안·신원 감사 범위를 확대하는 것.
- 관계: 003~017, 019~021. S08까지 필요한 동반 변경을 미루어 중간 단계를 깨뜨리지 않는다.

## 인수 기준

- AC-018-1: 전체 영향 목록에 누락 항목이 없고 변경 대상 및 유지 사유가 요구·구현·검증과 연결된다.
- AC-018-2: 관련 스킬·참조·도구가 같은 정본 경로와 준비 조건을 사용하며 provider 동기화·구조 검사가 통과한다.
- AC-018-3: 변경 훅 격리·배선·로그 경계가 유지되고 실제 provider 수행 결과와 미검증 한계가 구별되어 보고된다.
- 검증 연결: ACC-018.
