- 설계 진입점: [design/README.md](../design/README.md).

## 설계 결과

- CHG 주기/WRK 작업 재사용, 모듈·공통 단일 소유의 ID별 v2 JSON 정본을 설계했다.
- FEAT 기능 상세 명세 정본, DAT/NAV 분석 목록, RVW 검토·BSL 기준선·IMP 영향 판정의 책임을 구체화했다.
- 현재 내용과 역사적 원문 snapshot, 인덱스와 엄격한 scope 읽기, 협력 쓰기 conflict/저널/복구 계약을 분리했다.
- 전체 주기 요구 검토→작업별 기능/화면/목업 준비→개발/실행 증거→scope 릴리스, typed 간접 영향과 선택적 복귀를 설계했다.
- 기존 파일 367개를 10개 inventory 조각으로 분류했다. 유지 67/수정 108/구조 교체 52/재생성 140은 작업량이나 완료율이 아니다.
- 기존 36개 CLI 명령의 보존/확장/대체, 모든 portable 17개+관리 1개 스킬과 references, 독립 훅 13개를 대상으로 처리 계획을 기록했다.
- KIT-ADR-006~009는 proposed다. S03 착수 승인을 설계안 승인으로 확대하지 않았다.

## 작업 중 사용자에게 명확히 설명한 경계

- FEAT JSON 정본을 새로 만든다는 뜻이며, 구형에는 FEAT 정본이 없어 기존 FEAT ID를 보존한다는 의미가 아니다.
- 기존 ID/이력 보존은 이미 수행 중인 제품 프로젝트가 새 구조를 명시적으로 채택할 때 REQ/SCR/TC/CHG/HIS/EVD 등의 연결과 과거 사실을 유지하는 것이다. 구형/신형 정본을 두 벌로 운영하지 않는다.
- 신규 프로젝트는 처음부터 v2로 시작한다. 현재 kit-source에는 실제 제품 데이터를 옮기지 않으며 fixture는 회귀 입력이다.
- 이번 전환 설계는 현재 공식 v1 형식→v2 후보 변환이다. 자동 Kit 파일 업데이트나 모든 미래 버전 전환 보증이 아니다. 실제 도구 구현·검증은 S09다.
- 사용자 질문에 대한 설명은 범위 해석을 명확히 한 것이며 요구사항 개정 1의 의미를 변경하거나 설계 수용을 추가로 승인받은 것으로 기록하지 않았다.

## 자체 확인과 실제 검사

- 요구 21개와 ACC/E2E를 설계/후속 시험에 연결했다.
- 정의 승인 뒤 단순 authoring 상태 변경, 분석 목록의 정상 상세화가 자기 승인을 계속 무효화하는 설계 문제를 찾아 hash/projection 계약으로 구별했다.
- 설계 실행 모델 6/6 통과: 정의/실행 hash 분리, 분석/상세 투영, 후속 실패, 전이/순환, scope 미결, 임시 파일 rename과 과거 원문 보존.
- hook self-test, Kit quick check, Kit 관리 경계 테스트 1/1 통과.
- inventory 경로 집합 367개 중복/누락 없음, CLI 명령 36개와 요구 21개 매핑 확인.
- 관리 JSON·로컬 링크·UTF-8 BOM 없음/LF·검토본 해시·git diff --check 확인.
- 초기 Node 안에서 git을 spawn한 inventory 조회는 sandbox EPERM으로 미실행이었다. PowerShell의 직접 Git 조회와 파일 해시 계산으로 대체하여 완료했다. 이를 실제 기능 시험 실패나 통과로 계산하지 않았다.
- 일반 조회 시 현재 요구 검토본 25개는 해시가 그대로임을 확인했다. 제출 당시 검토 대기 서술은 역사적 문서이며 현재 승인 상태는 status.json의 APR-003이다.

## 미검증·미구현

- 새 portable 저장/조회/게이트/목업/전환 기능, 실제 다중 writer 및 crash 복구, 대규모 성능, 실제 계정 전환/provider 동작은 아직 구현/인수하지 않았다.
- 이번 6건 모델 검사는 실제 제품 테스트나 독립 검토가 아니다. 파일 교체 실험은 이 환경의 단일 rename 동작만 확인했다.
- 공개 코드·스킬·훅·fixture·export를 변경하지 않아 sync-providers·제품 인수·smoke는 실행하지 않았다.
- 실제 Kit 버전 변경·커밋·태그·릴리스 준비·배포는 하지 않았다.
