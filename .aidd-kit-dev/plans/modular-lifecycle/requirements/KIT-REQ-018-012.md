# KIT-REQ-018-012 — 화면 계약과 실제 검토 가능한 목업

- 출처: 사용자 화면 명세·목업 완료 후 개발 요청 / 계획 목표 7~8
- 목적: 제목만 있는 목업이나 과거 화면 승인을 실제 화면 설계 완료로 오인하지 않는다.
- 대상·트리거: UI 기능의 화면 설계·검토, 화면 또는 공통 UI 기준 변경.

## 요구 동작

- 화면 명세는 사용자·목적·진입/이탈, 메뉴·탐색, 표시/입력 항목과 데이터 참조, 동작, 정상·빈 값·오류·로딩 등 적용 상태, 검증·권한·접근성 조건을 표현한다. 요구에 없는 보안 체계를 임의 도입하지 않는다.
- 목업은 검토 대상 흐름·상태·상호작용을 확인할 수 있는 화면이어야 한다. 구현 전 결정에 필요한 범위를 넘는 실서비스 연동은 요구하지 않는다.
- 검토는 화면·관련 기능·UXB/UIP/CMP 등 실제 사용한 입력과 목업 결과를 식별하고, 검토 범위·사용자 결정·미결을 기록한다. 파일 존재나 생성 성공만으로 검토 완료가 되지 않는다.
- 생성기·스타일·공통 컴포넌트 등 표현에 영향을 주는 입력 변경도 관련 목업 검토의 영향 후보로 추적한다. 영향이 없는 경우는 근거를 남겨 기존 검토를 재사용한다.
- 목업은 구현 증거·실제 화면·운영 승인과 구분한다. 재생성 시 같은 입력의 결과 비교가 가능하도록 비결정적 메타데이터 처리 방식을 정한다.

## 범위·관계

- 포함: 의미 있는 목업과 그 검토의 유효성. 비UI 기능은 화면·목업 비적용 사유를 확인한다.
- 제외: 모든 목업을 완성된 프런트엔드로 구현하거나 모든 플랫폼에 특정 UI 기술을 강제하는 것.
- 관계: 005~007, 011, 013~014, 017, 021.

## 인수 기준

- AC-012-1: 대표 화면의 정상·오류 흐름과 입력·동작을 목업에서 확인하고 해당 개정본에 대한 사용자 검토를 추적한다.
- AC-012-2: 제목만 있는 파일·미검토 목업·내용 변경 전의 승인은 개발 준비 조건을 충족하지 않는다.
- AC-012-3: 관련 공통 UI 입력 변경의 영향을 판정하고, 비UI 기능에는 억지 화면·목업을 만들지 않는다.
- 검증 연결: ACC-012.
