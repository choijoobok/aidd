# 기술 스택과 개발 기반 게이트

## TSP-001 — 기술 스택과 개발 기반 우선 정책

- 상태: `최신`
- 요구사항: REQ-011, REQ-016, REQ-017, REQ-020, REQ-021

### 필수 순서

1. DG-001에서 배포·운영 맥락과 미결사항 확인
2. 성과·요구사항·품질 속성·워크로드·동시성 불변 조건 확정
3. TG-001 기술 스택 선정 게이트
4. TG-002 개발 기반 준비도 게이트
5. 기능 증분 계획
6. 기능 개발과 검증

**테일러링 규칙:** UI가 없는 제품은 UI 증거를 적용 대상 아님으로 기록할 수 있지만, 아키텍처·보안·테스트·관측성·배포·개발 표준은 생략할 수 없다. 기존 시스템은 현행 스택 유지를 기본 대안으로 포함한다.

## TG-001 — 기술 스택 선정 게이트

- 상태: `최신`
- 담당: 아키텍처
- 요구사항: REQ-005, REQ-010, REQ-011, REQ-016, REQ-017, REQ-020, REQ-021

### 적용 조건

- 신규 시스템
- 신규 모듈
- 핵심 런타임·프레임워크·데이터 저장소 변경
- 지원 종료·보안·비용·성능으로 현행 스택 재검토가 필요한 경우

### 진입 기준

- DG-001 통과 또는 유효한 배포 프로필 확인
- 성과와 범위가 정의됨
- 기능·비기능 요구사항과 품질 속성·워크로드·동시성 불변 조건이 식별됨
- 보안·개인정보·규제·예산·일정·팀 역량 제약이 기록됨

### 평가 차원

- 요구사항과 품질 속성 적합성
- 팀과 AI 도구의 숙련도
- 생태계 성숙도와 지원 수명
- 보안·공급망·라이선스
- 데이터·개인정보·규제
- 개발 생산성과 테스트 가능성
- 배포·관측성·복구·운영 부담
- 비용과 공급자 종속
- 상호운용성·마이그레이션·가역성

### 필수 증거

- 현행 유지안을 포함한 실행 가능한 후보 비교
- 추천안과 고객 결정을 분리한 ADR
- 버전·지원 기간·책임자·재평가 조건이 있는 기술 기준선
- C2·C3 또는 핵심 불확실성에는 타임박스된 실험·프로토타입 결과
- 보안·라이선스·운영·데이터 관점 검토

### 종료 기준

- 선택이 요구사항과 품질 속성 ID로 추적됨
- 채택하지 않은 대안과 비용·위험·가역성이 기록됨
- 고객이 중대한 비용·종속·잔여 위험을 승인함
- 기술 기준선이 승인되고 TG-002의 입력으로 연결됨

### 재평가 조건

- 핵심 요구사항 또는 품질 속성 변경
- 지원 종료·중대 취약점·라이선스 변경
- 실험이나 운영에서 기준선 가정 반증
- 새 모듈이 기존 경계를 넘는 기술을 요구

- 새 규제·보안·접근성 요구

## TSB-001 — AIDD 기반 구조 기술 기준선

- 범위: 이 저장소의 방법론 프레임워크와 CLI
- 상태: `승인됨`
- 요구사항: REQ-001, REQ-002, REQ-011, REQ-013

**결정:** 외부 런타임 의존성을 최소화한 Python 표준 라이브러리 CLI, 버전 관리되는 JSON 정본, 생성 Markdown, Git 훅, 공통 SKILL.md와 플랫폼별 얇은 어댑터를 사용한다.

### 기술 선택

| 영역 | 선택 | 근거 |
|---|---|---|
| 런타임 | Python 3.11 이상 표준 라이브러리 | 이식성과 설치 부담 최소화 |
| 정본 | UTF-8 무 BOM JSON | 결정적 파싱과 도구 독립성 |
| 사람용 문서 | 정본에서 생성한 한글 Markdown | 검토성과 재현성 |
| 변경·자동화 | Git, 저장소 훅과 Python 검증기 | 로컬·CI에서 같은 게이트 실행 |
| AI 어댑터 | 공통 SKILL.md와 Codex·Claude 네이티브 설정 | 의미 동등성과 플랫폼 호환성 |

### 적용 대상 아님

- 현재 CLI 기반 구조에는 제품 UI 디자인 시스템과 UI 공통 컴포넌트가 없다. 실제 UI 제품을 시작할 때 TG-002에서 필수로 전환한다.
