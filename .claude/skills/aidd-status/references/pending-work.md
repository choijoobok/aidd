# 보류와 재검증 브리핑

다음 항목은 완료·진행률과 섞지 않고 별도 구역으로 보고한다.

- 미결사항과 가정: 판단 조건·필요 시점, 영향받는 결정·모듈. 일반 미결 `OI`와 사용자 답변을 실제로 기다리는 `DRQ`를 구분한다.
- 결정 요청: `draft`, `awaiting_decision`, `deferred`, 답변 대기 묶음 수와 차단 건수를 분리한다. 브리핑 마지막에는 차단·명시적 우선순위·대기 시각으로 선택한 DRQ 묶음의 저장된 질문·선택지·권장안을 표시하고 상세 뷰에는 나머지 큐를 유지한다.
- 결정된 표준 예외: 보완 통제, 만료와 재검토 상태.
- 병합 후 대기 `MRC`: 영향 계약·모듈, 대상 테스트, 필요한 증거와 릴리스 차단 여부. 사전 담당자는 두지 않고, 완료된 뒤 실제 수행자·시각·결과를 기록한다.
- 연기된 범위: `나중 수행` 근거와 다시 열 조건.
- 검증 부담: 슬라이스별 남은 테스트·환경·데이터 준비.

과거 완료 이력과 현재 릴리스 준비를 분리한다. 재검증이 미완료이면 이전 `done`을 삭제하지 않지만 현재 릴리스 준비 완료라고 표현하지 않는다.

사용자가 다른 일을 계속 요청했다는 이유로 DRQ를 해결하거나 폐기하지 않는다. 독립 작업에서 새 결정이 생기면 실제 미결 대상을 먼저 저장하고 새 DRQ 묶음을 추가할 수 있다. 의존 작업이나 게이트 통과 요청에서는 관련 질문과 차단 영향을 다시 보여준다.
