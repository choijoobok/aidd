# 브리핑 뷰

레거시 역분석은 `legacy_reviews`의 단계별 total/pending/missing, 항목별 current/stale와 일반 요구 준비도를 분리해 보고한다. 실제 사용자 답변은 DRQ 묶음과 RVW/HIS를 확인하고, 재분석 IMP pending은 미결로 유지한다. 상세 절차는 [검토·재분석 계약](../../../../.ai/spec/legacy-review-reanalysis.md)을 따른다.

`legacy_adoptions`는 [도입·검증 계약](../../../../.ai/spec/legacy-adoption.md)의 동일 모델이다. documentation/readiness와 blockers, adoption/current·stale, runtime/TC별 결과·증거 ID를 구분하고 source_check.checked=false이면 현재 파일을 검사한 것으로 보고하지 않는다. 모듈 A의 운영 이력은 B의 도입 준비와 별도다.

v2 모듈/상세 뷰에는 discovery의 선행 업무 분석 판정을 요구/개발 준비도와 별도로 표시한다. 핵심 업무·역할 목표·유즈케이스·프로세스 단계의 누락과 검토 current/stale를 구분한다. 운영 중인 모듈에 새로운 분석 주기가 있어도 운영 이력을 미완료로 되돌리지 않는다.

- 경영진: 성과 상태, 단계, 배포·기술 게이트와 릴리스 신뢰도, 차단사항, 치명적 위험, 최신 주요 결정, 기록된 경우 예산·일정 신호, OI와 DRQ의 구분된 건수·묶음 수, 권장 다음 작업과 다음 이정표. 우선 답변할 DRQ 묶음은 마지막에 둔다.
- 모듈: 목적, 상태, 배포 프로필·토폴로지, `WRK` 작업 상태, `IFC` 계약, `DPN` 의존성, 요구사항·테스트 수, 진행 변경, 적용 설계 위험, 차단된 인터페이스, 다음 작업.
- 상세: 영향받는 각 요구사항·변경·테스트·마일스톤·작업·인터페이스·의존성·배포 가정·설계 위험·게이트 실행·결정·증거·예외·미결사항·결정 요청, 상태와 정확한 차단 원인. 담당자와 일정은 외부 프로젝트 운영 정보가 제공된 경우에만 참고 정보로 표시한다.

`not_run`, `unknown`, `failed`를 하나의 상태로 합치지 않는다. 계획된 작업을 진척 증거로 표현하지 않는다.

AI 평가에서는 Codex와 Claude의 각 실행 슬롯을 표시하고, 저장소 보호에서는 로컬 구성과 원격 활성화를 분리한다.

사람 신원·권한은 AIDD의 기본 판정 범위가 아니다. 사용자가 별도로 요청한 경우에만 확인 범위와 한계를 보고한다.
