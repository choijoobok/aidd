# Unreleased changes

- 각 KIT-CHG의 `version_impact`를 집계해 다음 SemVer를 계산하는 `release-plan`과, 검증 완료·깨끗한 작업 트리·버전 정합성을 확인한 뒤 두 버전 정본·`released_in`·릴리스 노트·UNRELEASED를 함께 갱신하는 `prepare-release`를 추가했다. 커밋과 Git 태그는 자동 생성하지 않는다.
- 요구분석·설계·개발·검증·출시·운영 전반의 미결 결정을 프로젝트 전체 공통 OI에 먼저 저장하고 단계별 정본을 링크하며, 실제로 사용자에게 물은 질문은 `workboard.decision_requests`의 DRQ로 질문 전에 기록하도록 했다. 여러 미응답 묶음을 보존하며 `status`는 OI와 DRQ 건수·묶음 수를 구분하고 차단·우선순위·대기 시각으로 고른 권장 질문을 마지막에 표시한다. bootstrap에서도 채워진 정본을 고정 문구로 가리지 않고 기존 workboard의 배열 누락은 빈 목록으로 호환한다.
- Claude 런타임 훅을 provider의 실제 입력·출력 계약에 맞췄다. Stop은 응답 본문 필드가 없는 Claude Code 입력에서 transcript_path의 마지막 assistant 텍스트만 읽어 대화 로그를 기록하고, PostToolUse 안내는 모델이 볼 수 있는 비차단 exit 2로 전달한다. 생성물 보호는 도구 입력의 경로 필드를 대상으로 판정하고 역슬래시를 정규화해 Windows 경로 우회와 내용 기반 우회를 막으면서 생성물 경로를 언급하는 문서 편집은 차단하지 않는다. Codex 훅의 명령·등록 위치·승인 해시는 바뀌지 않는다.
- 훅 격리를 1순위 불변 규칙으로 채택해 provider·이벤트·책임마다 공통 코드 없는 전용 `.ai/hooks/*.mjs` 프로세스로 분리하고 기존 등록 위치를 회귀 테스트로 고정했다. Claude·Codex 대화는 `UserPromptSubmit`에서 provider·세션·턴별로 임시 보관한 질의와 `Stop`의 최종 응답을 `Codex` 또는 `Claude`가 표시된 한 블록으로 결합하고, 동시 세션 잠금 아래 현재 프로젝트 루트의 `chat-history/YYYY-MM/raw/YYYY-MM-DD.md`에 append한다. 한쪽만 있는 블록과 중복 Stop은 기록하지 않으며 기존 일자 파일은 이동하지 않는다.
- 수식어 없는 요구사항은 `REQ` 제품 요구사항으로 한정하고, 개발 단계 산출물을 `기능 상세 명세서`와 `화면 명세서(SCR)`로 분리했다. 비정본 `FEAT`·`USE` 표기를 제거하고 유즈케이스를 `UC`로 통일했으며, 화면 파생 문서 경로를 `requirements.md`에서 `specification.md`로 변경했다.
- 참여자·Git 신원·PM 권한·사람 승인·작업 배정 관리를 프로젝트 외부 운영 영역으로 분리하고, AIDD는 안정 ID에 연결된 결정 이유·영향·대체 이력과 실행·검증 산출물에 집중하도록 단순화했다.
- 의미 있는 분석·설계·용어·소스·정본 변경에 대해 자유문자 결정자, 이유, 영향 ID와 출처를 남기는 `HIS` 결정 이력 조각과 생성 뷰를 추가했다.
- 프로젝트 팀 사용법을 `project-team-guide.md` 단일 진입점과 준비·생명주기·문서·스킬/훅·팀 작업·완료/출시 상세 장으로 재구성하고, 각 흐름을 자연어로 AI에게 요청하는 예시를 추가했다.
- Kit 원본과 배포 프로젝트의 `AGENTS.md`, `CLAUDE.md`, `README.md`를 역할별로 대조하고 같은 이름이지만 목적이 다른 두 문서 묶음의 경계를 명시했다.
- Kit 유지보수 관리자 절차를 저장소/문서 경계, 변경/검증, export/릴리스 장으로 분리하고 프로젝트 배포 문서에서 관리자 전용 명령을 제거했다.
- reference fixture의 일상 검증 문구를 전체 Node 테스트 강제에서 변경 영역 테스트로 현행화했다.
- Codex CLI·Windows 앱의 매 세션 시작에 CLI `/hooks`에서 작업공간 훅 검토·신뢰 여부를 확인하라는 경고를 표시하고 Claude에서는 표시하지 않도록 했다.
- Windows 앱이 `systemMessage`를 대화에 표시하지 않는 경우에도 Codex 새 세션의 첫 최종 응답(`final_answer`)에서 `/hooks` 확인 안내가 보이도록 모델 컨텍스트 경로를 복구했다. 접히는 진행 메시지에 먼저 표시됐더라도 첫 최종 응답에서 다시 표시하되, 이전 assistant 최종 응답에 이미 표시됐다면 이후 응답에서는 반복하지 않는다. 하위 폴더에서 시작한 세션도 Git 루트 또는 작업공간 역할 표식 기준으로 훅 실행기를 찾으며, 이 안내는 승인 상태를 저장하거나 작업을 차단하지 않는다.
- 스킬 변경 후 동기화 안내를 작업공간 역할에 맞게 분리해 Kit 원본은 `sync-providers`, 배포 프로젝트는 portable `sync-ai`를 사용하도록 했다.
- 새 용어 발견·영향 카드·오프라인 결정 결과 적용·용어집 검증을 자동 선택 가능한 `aidd-terminology` 스킬로 분리하고, 특정 역할이나 Git 신원 없이 현재 `TRM`과 append-only `TCH` 이력을 함께 관리하도록 정리했다.
