# 요구사항 포괄성·후속 연결 — 개정 1

전체 계획의 목표와 기존 발견사항이 [요구사항](README.md)에 빠짐없이 연결되는지 확인하는 관리용 추적표다. 세부 요구는 각 파일이 정본이며 이 표에 내용을 복제하지 않는다. 현재 구현/인수 완료를 의미하지 않는다.

## 기존 확인 결과의 연결

출처는 [계획의 선행 검토 요약](../plan.md)이다. 과거 시험의 통과/실패를 새 구조의 검증 결과로 재사용하지 않는다.

| 기존 코드/재현에서 확인한 사실 | 유지·보완할 요구 | 후속 인수 |
|---|---|---|
| 운영 후 새 모듈 추가와 기존 요구 보존 가능 | 001, 019 | ACC-001, ACC-019, E2E-001 |
| 알 수 없는 모듈 의존 거부, 하위 요구 조각 로딩 가능 | 008~009, 014, 021 | ACC-008~009, ACC-014, ACC-021 |
| 빈 모듈 done 판정 허용 | 001, 015 | ACC-001, ACC-015 |
| blocked 선행 WRK에도 개발 허용 | 013, 021 | ACC-013, ACC-021 |
| 후속 failed가 있어도 과거 passed 인정 | 007, 015 | ACC-007, ACC-015 |
| 무관한 모듈 OI/DRQ가 다른 릴리스 차단 | 006, 015~016 | ACC-006, ACC-015~016 |
| 단일 모듈 조회도 모든 본문 로딩 | 008~009 | ACC-008~009 |
| 요구 상세/검토보다 상위 설계 상태 선언 신뢰 | 002~007, 015 | ACC-002~007, ACC-015 |
| 목업이 제목 중심이며 기능 명세 정본 미채택 | 011~013 | ACC-011~013 |
| 전역 큰 파일·모듈 상세 한 문서 | 008~010, 017 | ACC-008~010, ACC-017 |

## 단계 간 산출물 연결

| 현재 입력/산출물 | 다음 연결 | 단계를 넘기지 말아야 할 조건 |
|---|---|---|
| 사용자 의도·합의 범위·적용 공통 조건 | 상세 요구·분석 목록 | 중요한 모호성·범위 이견 |
| 상세 요구·정합성/사용자 검토·유효 기준선 | 기능·화면·데이터/접점 상세 설계 | 현재 주기 요구 중 미완성·미검토·해결되지 않은 충돌 |
| 검토된 기능/화면/목업·테스트 계획 | 준비된 WRK 개발 | 관련 명세·목업·선행 결과 부족 |
| 구현과 실제 실행·통합 증거 | 범위별 릴리스·운영 기준선 | 관련 실패/미실행·미결 결정·현재 입력과 불일치 |
| 어느 단계에서든 발견한 변경 | 영향 후보→판정→필요 단계 복귀 | 영향 미확인인 범위를 자동 준비 완료 처리 |
| 같은 정본·준비도 | 브리핑·문서·매뉴얼·제출물 | 생성물 수동 편집·다른 상태 해석·오래된 출력 |

## 검증 배분과 완료의 의미

- S02: 21개 요구의 적용 조건·63개 인수 기준·21개 항목별 시나리오와 1개 전체 흐름을 검토한다. 문서 구조/링크·관리 상태를 검사하며 실제 기능 시험으로 보고하지 않는다.
- S03: 모든 요구를 설계 책임·영향 자산·테스트 접근에 연결하고 기존 계약 대체/보존·실패 복구를 결정한다.
- S04~S09: 해당 요구의 정상·부정·경계 행위를 구현하고 실제 결과를 연결한다. 당시 바뀐 명세·스킬·가이드도 함께 갱신한다.
- S10: 인수 시나리오와 실제 증거의 누락을 확인한다. 의미 검토/사용자 화면 평가/실제 provider 실행과 자동 구조 검사를 분리해 보고하고 미검증을 완료로 숨기지 않는다.
- 요구가 바뀌면 이 추적표와 관련 시나리오·설계/검증 연결을 같이 재검토한다. 불변인 과거 이력이나 무관한 결과는 삭제하지 않는다.
