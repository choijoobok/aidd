# S08B-3 — 모듈별 문서 관리 채택·기존 구현 검증 연결 완료

APR-012 승인 범위만 구현했다. [portable 계약](../../../../.ai/spec/legacy-adoption.md), [팀 사용 안내](../../../../.ai/docs/guides/legacy-reverse-workflow.md), KIT-ADR-014를 따른다. S02/S03와 S08B 요구 제출본은 불변이다. 현재 단계/다음 승인은 [status.json](../status.json)을 따른다.

## 결과

- `legacy-adoption-check --change --module`: 한 모듈 CHG 전체의 순차 검토·일반 요구 게이트·자료 현행·검증/현행-목표 차이 계획을 확인한다. 공통 정의는 참조하며 다른 모듈의 미래 초안/깨진 정본을 채택의 전역 장벽으로 만들지 않는다. 다중 모듈 CHG의 일부만 승인하지 않고 먼저 독립 CHG로 나눈다.
- 기존 DOC에 검증 계획을 둔다. 실제 TC/REQ/AC·정상/예외/데이터 경계, 사용자 판단, 현행 유지/수정/개선/폐기와 필요한 WRK, 기존 화면 재사용 근거를 연결한다. 계획의 현재 사용자 검토가 필요하다.
- `legacy-adopt --input --operation`: 실제 사용자 판단·최신 document_digest·source-check·관련 정본 CAS를 확인해 DOC/HIS만 저장한다. 기존 정본과 CHG/WRK/REL의 실행 상태·운영 이력을 초기화하지 않는다. 동일 요청 replay와 중단 transaction 복구를 재사용한다.
- 실제 검증 상태는 문서 채택과 분리한다. EVD를 계획·TC·요구·자료·환경에 묶어 not_run/passed/failed/stale/invalid/ambiguous를 표시한다. 최신 실패를 과거 통과로 가리지 않는다. 조회나 채택은 제품 코드를 실행하지 않는다.
- 기존 화면 검토를 과거 prototype 승인으로 생성하지 않는다. 새 CHG/WRK는 같은 정본 ID를 참조하고 정상 요구·기능/화면·목업·테스트 게이트를 계속 따른다.
- 상태/파생 문서는 동일 순수 모델을 사용하되 저장된 자료 기준임을 표시한다. 파일 변경까지 확인하는 채택 명령과 구분한다. legacy/status 스킬·가이드·public manifest/spec index·두 provider를 동기화했다. 새 runtime 훅/실행기/스킬/정본 유형은 없다.

## 한계·호환성·롤백

문서 채택은 실제 동작 검증이나 운영 배포 완료가 아니다. 테스트 기록의 적합성을 검사할 뿐 실제 실행의 진실성이나 제품 품질을 도구가 보증하지 않는다. 계획/결정·관측의 의미는 사용자와 AI가 검토해야 한다. 아직 모든 언어/Office/PDF의 자동 의미 파서를 제공하지 않으며 실제 고객 자료 검증은 별도다.

관련 모듈/공통 파일을 읽고 선언 루트를 재수집한다. 운영 시스템에는 접속·실행하지 않는다. 저장된 브리핑이 현재 파일 검사 결과를 대신하지 않으며 source_check.checked를 함께 표시한다. source scan과 commit 사이 비협력 외부 writer/분산 FS의 완전 원자성은 보장하지 않는다. 무관 모듈이 깨졌으면 정본 채택 성공과 전체 index stale을 구별한다.

호출하지 않으면 자동 실행이 없다. 미완료 저장은 transaction-status/recover로 명시 처리한다. 완료한 문서 채택은 기존 DOC/HIS와 후속 편집을 보존하는 새 정상 변경으로 정정한다. 일괄 삭제/초기화·구버전 AIDD 변환·자동 운영 데이터 이관은 하지 않는다.

S08B-1~3 기능 구현을 마쳤다. 전체 KIT-CHG-018은 major/in_progress, 버전 1.0.0 유지. 실제 고객 적용·커밋·태그·릴리스 없음. 다음은 KIT-DRQ-018-05의 축소된 S09(신규 v2 프로젝트/export·fixture/스켈레톤/CI·구형 writer 격리)이며 S10 최종 인수도 아직 남아 있다.
