# 프로젝트 수행 생명주기

프로젝트 수행 생명주기는 루트 `AGENTS.md`와 `.ai/skills/`의 계약을 따른다. 제품 정본은 `project/.aidd/ssot/`, 파생 문서는 `project/docs/generated/`, 제품 소스는 `project/src/`에 둔다.

수행팀은 의도·성과·범위 확인, 필요한 외부 조사, 요구·설계·표면 문서화, 위험 비례 게이트, 작은 구현 증분, 검증 증거, 출시·운영의 순서로 일한다. 배포된 Kit 파일도 프로젝트 상황에 맞게 바꿀 수 있지만 변경 이유, 영향과 검증 결과를 프로젝트 정본과 결정 이력에 남긴다.

인력 구성, 역할, PM 위임, 작업 배정, 일정과 승인 권한은 AIDD 밖의 프로젝트 운영 사항이다. AIDD는 이를 위한 사람·신원·권한 정본을 만들거나 실행 조건으로 검사하지 않는다. 프로젝트가 정한 결과를 제품 범위·우선순위·게이트 상태에 반영할 때는 결정 주체를 자유문자로 기록할 수 있지만 이는 인증이나 권한 검증이 아니다.

## 결정 기록

현재 항목에는 현재 상태와 핵심 근거를 둔다. 분석·설계·용어·소스·범위·상태를 바꾸는 의미 있는 결정은 `record-history`로 `HIS`에 기록하고 관련 `REQ`, `ADR`, `CHG`, `TRM`, `SURF`, `WRK` 등의 안정 ID를 연결한다. 정확한 파일 차이는 Git에서 확인하며 HIS는 누가 또는 어떤 협의체가 왜 결정했고 어떤 영향이 예상되었는지를 설명한다. 장기 아키텍처 선택은 ADR, 실행 범위는 CHG, 용어 변경은 TCH를 함께 사용한다.

## 용어 변경

공통 AIDD 용어는 `.ai/manifests/terminology.json`의 뜻을 사용한다. 프로젝트 용어는 개념 유형, 범위, 별칭, 사용 예, 관련 용어와 혼동 구분을 기록한다. 새롭거나 모호한 용어는 기존 용어를 먼저 검색하고, 필요하면 읽기 전용 `term-review`로 영향 카드를 만든다. 프로젝트가 오프라인 절차로 결정한 뒤 `term-apply --decided-by "결정 주체" --summary "이유와 요약"`를 실행한다. AI는 현재 `TRM`과 전후 값·영향·결정 주체·적용·검증을 담은 `TCH`를 저장하고 용어집과 관련 파생 문서를 다시 생성한다. 특정 PM 역할이나 Git 계정 일치를 요구하지 않는다.

Kit 원본과 개별 프로젝트는 서로 자동 동기화하지 않는다. 개선은 각 환경에서 별도 변경으로 영향 분석·구현·검증한다.
