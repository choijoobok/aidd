# Unreleased changes

- 참여자·Git 신원·PM 권한·사람 승인·작업 배정 관리를 프로젝트 외부 운영 영역으로 분리하고, AIDD는 안정 ID에 연결된 결정 이유·영향·대체 이력과 실행·검증 산출물에 집중하도록 단순화했다.
- 의미 있는 분석·설계·용어·소스·정본 변경에 대해 자유문자 결정자, 이유, 영향 ID와 출처를 남기는 `HIS` 결정 이력 조각과 생성 뷰를 추가했다.
- 프로젝트 팀 사용법을 `project-team-guide.md` 단일 진입점과 준비·생명주기·문서·스킬/훅·팀 작업·완료/출시 상세 장으로 재구성하고, 각 흐름을 자연어로 AI에게 요청하는 예시를 추가했다.
- Kit 원본과 배포 프로젝트의 `AGENTS.md`, `CLAUDE.md`, `README.md`를 역할별로 대조하고 같은 이름이지만 목적이 다른 두 문서 묶음의 경계를 명시했다.
- Kit 유지보수 관리자 절차를 저장소/문서 경계, 변경/검증, export/릴리스 장으로 분리하고 프로젝트 배포 문서에서 관리자 전용 명령을 제거했다.
- reference fixture의 일상 검증 문구를 전체 Node 테스트 강제에서 변경 영역 테스트로 현행화했다.
- Codex CLI·Windows 앱의 매 세션 시작에 CLI `/hooks`에서 작업공간 훅 검토·신뢰 여부를 확인하라는 경고를 표시하고 Claude에서는 표시하지 않도록 했다.
- Windows 앱이 `systemMessage`를 대화에 표시하지 않는 경우에도 Codex 새 세션의 첫 최종 응답(`final_answer`)에서 `/hooks` 확인 안내가 보이도록 모델 컨텍스트 경로를 복구했다. 접히는 진행 메시지에 먼저 표시됐더라도 첫 최종 응답에서 다시 표시하되, 이전 assistant 최종 응답에 이미 표시됐다면 이후 응답에서는 반복하지 않는다. 하위 폴더에서 시작한 세션도 Git 루트 또는 작업공간 역할 표식 기준으로 훅 실행기를 찾으며, 이 안내는 승인 상태를 저장하거나 작업을 차단하지 않는다.
- 스킬 변경 후 동기화 안내를 작업공간 역할에 맞게 분리해 Kit 원본은 `sync-providers`, 배포 프로젝트는 portable `sync-ai`를 사용하도록 했다.
- 새 용어 발견·영향 카드·오프라인 결정 결과 적용·용어집 검증을 자동 선택 가능한 `aidd-terminology` 스킬로 분리하고, 특정 역할이나 Git 신원 없이 현재 `TRM`과 append-only `TCH` 이력을 함께 관리하도록 정리했다.
