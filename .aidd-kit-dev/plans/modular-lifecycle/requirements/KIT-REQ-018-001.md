# KIT-REQ-018-001 — 모듈별 개발 주기와 운영 공존

- 출처: 사용자 의도 — 모듈별 독립 주기, 완료 후 신규 모듈 추가 / 계획 목표 1~2
- 목적: 이미 운영되는 결과를 보존하면서 새 모듈과 기존 모듈의 후속 개발을 진행한다.
- 대상·트리거: 수행팀/AI가 모듈을 추가하거나 기존 모듈의 신규 변경을 시작할 때.

## 요구 동작

- 프로젝트 공통 조건, 모듈의 소유 범위·운영 기준선, 이번 개발 범위, 기능/화면 작업을 구분한다.
- 모듈마다 운영 기준선과 활성 개발 범위를 동시에 표시한다. 하나의 프로젝트 단계나 모듈 상태로 모든 작업의 진행을 덮어쓰지 않는다.
- 새 모듈은 요구분석부터 시작하고 기존 모듈의 정본·운영 상태·과거 완료를 변경하지 않는다. 영향이 발견되면 014에 따라 관련 부분을 다시 검토한다.
- 같은 모듈의 복수 활성 변경도 구분한다. 같은 계약을 동시에 바꾸는 경우 충돌·의존을 표시하고 묵시적으로 합치지 않는다.
- 완료는 식별된 개발 범위와 산출물·검증에 귀속한다. 빈 모듈 또는 단순 상태 문자열 변경을 완료 근거로 사용하지 않는다.

## 범위·관계

- 포함: 신규 구축, 추가 모듈, 기능 변경, 결함 수정, 운영 중 개선.
- 제외: 인력·일정 배정, 모듈별 독립 배포를 모든 제품에 강제하는 것.
- 관계: 002의 범위, 007의 상태, 015의 게이트, 019의 모듈 생성, 021의 계약에 의존한다.

## 인수 기준

- AC-001-1: A가 운영 중일 때 B를 추가하면 A의 기준선과 완료 결과가 유지되고 B의 요구분석 범위만 새로 식별된다.
- AC-001-2: 같은 모듈의 운영 버전과 요구분석 중인 후속 변경을 동시에 조회할 수 있다.
- AC-001-3: 빈 모듈을 완료로 표시하려 하면 필요한 범위·산출물·검증이 없는 이유를 제시하며 완료 판정을 거부한다.
- 검증 연결: ACC-001, E2E-001. 현재 실행 결과가 아닌 인수 조건이다.
